# 无 UI 协作组：设计与验收

2026-09-28，基于用户已认可的自然语言协作设计。实施基线为 `eecfa78`；本次修改现有 multi-harness 技能，不新增前端或后台常驻服务。

## 使用契约

当前 Codex 对话是唯一入口。用户可说“开一个研究组”“让研究员解释依据”“现在怎么样”“暂停”“继续 Jev 那个组”。Codex 解析自然语言和普通文本中的 @，调用确定性脚本；脚本不猜测语义、模型或授权。

开组时记录目标、策略、成员及验收标准。团队配置显式填写成员 ID、角色、CLI、固定模型、讨论模式和限额；可以保存并复用，组内使用配置快照。调用前沿用现有 CLI 探测。没有可用配置时由 Codex 根据本机已核验模型制定，不内置易失效的默认模型。

显式组名/ID 优先；其次当前对话绑定；没有绑定时，只能在当前项目恰好一个组时默认选择。多组不猜“最近一个”。同名和跨项目歧义必须报出候选。

## 讨论与执行

- 讨论成员仅拥有 advisor/researcher 能力，使用各自持久 CLI 会话。消息不会扩展工具权限。@文本本身不触发模型，Codex 将需跟进的问题明确入队；转述须保留原发言引用。
- 发给成员的消息排队；给 Codex 的消息只记录。一次派发只唤醒目标成员。组内先串行派发，每次调用有 turn 数上限，总调用数有限额，失败不自动重试。
- 接收方上下文包含当前目标/策略、Codex 决定、当前消息和明确引用的原消息。其他消息按需提供，不自动灌入全部历史。
- 每轮保留真实 CLI 输出、会话 ID、指定/报告模型和结果路径。状态为 queued、dispatched、replied、failed、cancelled 或 unknown；没有逐条已读 ACK，不报告已读。
- 普通追问走独立讨论会话。代码/文档执行继续使用原 ready 计划、run/revise/accept；可将该执行结果关联到组里，状态从原始证据读取，聊天不改任务验收。
- 任务所需同一文件的写入由 Codex 串行安排或隔离交付，结果验收后整合。现有 agy 隔离基线要求继续适用；不会自动提交用户源码来绕过干净基线要求。

## 持久状态与暂停

本地 SQLite 保存团队、组、对话绑定、消息、派发记录及任务关联，事务负责 claim，避免并发双重派发。模型运行期间不占写事务，新消息可以入队。日志及工作区保留在本地状态目录；也可按项目约定显式选择忽略目录。

暂停先设置组停止派发；正在执行的 CLI 收到取消请求，确认执行器返回后才显示 paused，此前为 pausing。恢复只解除暂停，不重发失败或结果不明的旧消息；Codex 根据队列继续 dispatch。对话关闭后没有后台继续聊天的承诺。

控制器意外退出时，已派发但未落库的消息保留 dispatched，status 明示恢复核验需求；reconcile 只接纳可核验的终止结果，不自动重发。没有终止证据时报告 unknown/待人工核对，不猜测已结束。会话 ID 缺失、变化或范围违规阻止该成员继续复用，保留证据。

## 已确认的测试接口

用户已确认完整链路：通过群组公开命令及 CLI 适配器测试开组、点名、状态、暂停、继续，并保留旧任务修订/验收回归。按 TDD 逐片实现，不验证私有方法或固定文案。

1. 创建后能在新进程中找回组，复用团队，歧义不误选。
2. 点名只向目标发送；新消息可排队；后续轮次传递真实 session ID；普通追问不更改已验收任务。
3. 状态查询零模型调用；消息来源真实可查，重复请求 ID 不重复入队或执行。
4. 执行中暂停能终止并确认，暂停状态不派发；恢复继续尚未派发的消息。
5. 超时、断流、模型/会话不一致、上限、并发派发和控制器异常均留下明确状态，不自动重发。
6. 用合成 CLI + 真实 subprocess/Git 验证协议，再做有限真实 Claude/agy 会话实测；前者不冒充真实模型验收。

## 实施范围

新增组状态/调度脚本与对话适配模块，复用 harness 的 CLI 参数、事件解析、范围检查和证据格式；原任务计划、修订及验收协议保持独立。更新 SKILL.md、按需读取的组操作指南及调用提示。最后执行全库测试、语法/技能校验与 Standards/Spec 独立审查。
