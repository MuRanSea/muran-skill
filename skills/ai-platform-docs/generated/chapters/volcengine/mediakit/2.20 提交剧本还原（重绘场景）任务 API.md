2.20 提交剧本还原（重绘场景）任务 API
POST https://mediakit.cn-beijing.volces.com/api/v1/tools/drama-script-vertical
本 API 用于提交一个异步的剧本还原（重绘场景）任务，通过分析多集短剧视频，输出可复用的角色、场景、预处理结果与逐集剧情分镜剧本，适用于短剧重绘、出海重制预处理、剧情解说等二次创作场景。使用方式
本工具支持多种使用方式，以适应不同的业务场景，如首次分析、剧集增量更新、或利用外部资产进行还原。核心在于通过 previous_manifest_url 和 current_asset_url 两个参数来控制任务的分析流程和数据复用。
场景一：首次分析
场景说明：当您需要从零开始分析一部短剧的前几集时。
使用说明：在 videos 数组中提供第一批视频的 URL 和对应的集数。任务将完整执行所有分析步骤，包括资产解析、预处理和剧本生成。
场景二：接续分析（增量处理）
场景说明：当您获得同一部短剧的后续剧集，希望在分析时复用已有资产（如角色、场景），以保证信息一致性时。
使用说明：在 videos 中传入新剧集的 URL，同时将上一次任务产出的 manifest.json URL 填入 previous_manifest_url 。系统会自动加载前序结果，确保新旧剧集中的同一角色被正确识别，保证剧情分析的连续性。
场景三：分步执行（先出资产，后出剧本）
场景说明：如果您希望在生成最终剧本前，先检查或手动修正资产分析（角色、场景等）的结果，或者希望分阶段控制成本，可以将整个任务拆分为“生成资产”和“生成剧本”两个步骤。
使用说明： 
生成资产与预处理结果：提交一个任务，在 videos 中传入视频列表，并将 return_type 设置为 
["asset", "preprocess"] 。任务完成后，您将获得包含资产和预处理结果的 manifest.json 文件。使用已有资产生成剧本：确认第一步产物无误后，提交一个新的任务。请求中依然传入相同的 videos 列表，但同时将第一步产出的 manifest.json URL 填入 current_asset_url 参数，并将 return_type 设置为 ["script"] 。此任务将跳过资产分析，直接利用您提供的资产生成剧本，从而节约时间和成本。

示例二：多任务接续分析
以下示例演示了如何分两次任务，完整分析一部 4 集短剧，并通过 previous_manifest_url 参数确保两次任务的资产信息（如角色）保持一致。
第 1 步：首次分析第 1-2 集
首先，提交一个任务来分析前两集。这是一个标准的首次分析任务，参考示例一：首次分析。第 2 步：接续分析第 3-4 集
当您获得了新的第 3 和第 4 集时，为了保证与前两集的资产信息保持一致，您需要在新任务中引用上一次的产物。在本次请求中， videos 列表里只包含新剧集，同时使用 previous_manifest_url 参数传入第 1 步中获取的 manifest.json 链接。
通过这种方式，第二个任务在处理第 3、4 集时，会加载并复用第一个任务分析出的角色和场景信息，确保整个短剧（1-4集）的资产和剧本具有良好的一致性。
示例三：分步执行（先出资产，后出剧本）
以下示例演示了如何将一次分析拆分为“生成资产”和“生成剧本”两步：先仅产出资产与预处理结果供检查或修正，确认无误后再复用该资产生成剧本，从而分阶段控制成本。
第 1 步：生成资产与预处理结果
首先，提交一个任务，传入待分析的视频列表，并将 return_type 设置为 ["asset", "preprocess"] ，使任务仅执行资产分析与预处理，暂不生成剧本。任务完成后，您将获得包含资产与预处理结果的 manifest.json 文件。

异步任务结果
剧本还原（重绘场景）是一个异步任务，任务的执行状态和最终结果不会在提交时同步返回。您可以通过以下两种方式获取任务结果：
方法一（轮询查询）： 使用提交任务时获取的 task_id ，定期调用查询任务信息 API，直到 status 字段变为 completed 或 failed 。
方法二（事件回调）： 在 AI MediaKit 控制台预先配置一个接收回调的 URL，或在提交任务时通过 callback_url 参数为单次任务指定回调地址。任务完成后，系统会将包含最终结果的详细信息 POST 到您指定的地址。详情请参阅事件回调。
