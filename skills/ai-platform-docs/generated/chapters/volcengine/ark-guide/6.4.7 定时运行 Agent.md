6.4.7 定时运行 Agent
当同一个 Agent 需要按固定节奏反复处理任务，例如每天生成业务日报、定期巡检数据或按月汇总线索，可以用 Deployment 保存一份可重复运行的 Session 启动配置。
Deployment 本身不执行任务，而是保存可复用的 Session 启动配置。到达计划时间或手动触发时，平台会基于这份配置创建新的 Deployment Run 和 Session。不同 Run 不复用对话上下文，每次运行都会从同一批初始事件开始。
了解运行对象
使用 Deployment 后，一个重复任务会拆成配置、启动记录、执行会话和初始事件模板。创建计划、临时补跑或排查结果时，先看当前问题属于哪一层，可以避免把“启动成功”误判为“任务完成”：注意
Deployment Run 只覆盖启动阶段，不覆盖 Agent 的后续执行。接口返回 session_id 后，继续查询 Session 详情和事件流，确认模型输出、工具调用和任务状态；不要只凭 Run 成功判断业务任务已经完成。
准备资源
开始前，完成以下准备：
创建方舟 API Key，并配置为 ARK_API_KEY 。
创建要运行的 Agent，并记录 Agent ID。
创建 Environment，并记录 Environment ID。
按需准备 Files、Memory Store 和 Vault。
对象 说明
Deployment
保存固定的 Agent 版本、Environment、初始事
件、资源、Vault 和触发计划。创建或更新后，
这份配置只供后续新启动的 Run 使用。
Deployment Run
记录一次手动或定时启动。Run 成功说明平台已
经创建 Session 并受理初始事件，后续 Agent 任
务是否完成要继续看 Session。
Session 承载一次实际执行。模型输出、工具调用、任务
状态和产物都在 Session 及其事件中查看。
Initial events 每个新 Session 收到的第一批事件。当前仅支持 
user.message 。

管理生命周期
暂停定时触发
暂停只停止后续定时触发，不会中断已经受理或正在运行的 Session。需要临时补跑时，暂停期间仍可调用立即运行接口。
恢复定时触发
恢复时，平台会重新校验固定的 Agent 版本、Environment、Vault 和 Memory Store。 type=file 资源是否可访问，仍在下一次 Run 启动时校验。恢复不会补跑暂停期间错过的计划，Deployment 会从下一个计划时间继续触发。

模型资源、文件可用性和临时凭据都会在 Run 启动时校验，所以创建 Deployment 不等于后续 Run 一定能启动成功。Agent 配置失效、文件无法访问或临时凭据获取失败时，Run 会失败；如果错误不可恢复，Deployment 还会被自动暂停。
如果挂载 type=file 资源，创建、更新或恢复 Deployment 时，平台只校验 file_id 和 mount_path 的格式。文件是否存在、当前账号是否仍有权限，会在每次 Run 启动时检查。校验失败时，本次 Run 失败，Deployment 也会自动暂停。
