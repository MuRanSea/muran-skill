3.5 决策评估（beta）
决策评估可通过 System One API 将文本、图片、视频或音频等输入转换为业务可直接使用的结构化判断结果，适用于内容分类、请求路由、风险评估和优先级判断等场景。它可以返回某个条件为真的概率、从固定选项集合中选择某个选项的结果和概率，或者根据评分标准给出分数。
注意
System One API 当前处于 beta 测试阶段。调用该接口时，必须在 HTTP 请求头中传入 ark-betasystemone-api: true 。支持模型与 API

步骤一：设置被评估内容
将需要评估的业务内容放入 state 。 state 应包含完成判断所需的事实、证据、业务对象和上下文信息，避免把判定规则混入被评估内容中。
步骤二：设置评估问题和判定标准
在 questions 中传入评估问题，并设置以下字段：
type ：设置问题类型，可选值为 noul 、 choice 或 score 。
instructions ：说明判断目标。
criteria ：补充判定边界、候选选项或评分档位。简单场景可以只设置 instructions ；需要更稳定的业务判断时，建议补充 criteria 。

进阶使用
多模态输入
当 state 同时包含文本、图片、视频或音频时，可传入多模态对象数组，并在 instructions 中说明每种材料的作用，区分“用户主张”和“材料证据”，避免模型仅凭文字描述替代证据判断。
多模态内容支持以下传入方式：
本地文件上传：
Files API 上传 （推荐）：适用于文件较大，或需要在多个请求中复用同一文件的场景。文件上传并变为可用后，可在 System One API 请求中引用该文件。
Base64 输入：适用于文件体积较小、无需复用文件的场景。
公网 URL 输入：适用于文件已存在公网可访问 URL 的场景。
说明
多模态内容的文件格式、大小、尺寸、数量、时长及 Files API 上传限制，详见图片理解 、视频理解 、音频理解 和文件输入(Files API) 。
同一图片、视频或音频需要在多次评估请求中复用时，建议在 state 中通过 file_id 引用素材。对同一个媒体元素，不要同时传入 file_id 、公网 URL 或 Base64。
多模态输入会增加请求处理时间；如需保持较低响应延迟，建议仅传入完成判断所需的图片、视频或音频内容。

使用限制与注意事项
System One API 返回结构化判断结果，不用于生成面向用户的自然语言回复；如需生成客服话术、摘要、解释或完整报告，建议使用 Chat API 或 Responses API 。
System One API 当前支持最大 128k 上下文窗口，单次请求中的 state 和 questions 共同占用上下文窗口。
使用 choice 时，建议在 criteria 中设置 其他 、 信息不足 或 无法判断 等兜底选项，避免证据不足时被迫命中业务分类。
使用 score 时，每道问题应只评估一个有序维度；不同问题的档位数量或档位含义不一致时， score不应直接横向比较。
批量评估、实时高并发评估或周期性任务中，建议控制请求并发；遇到限流或服务繁忙类错误时，使用指数退避重试。
