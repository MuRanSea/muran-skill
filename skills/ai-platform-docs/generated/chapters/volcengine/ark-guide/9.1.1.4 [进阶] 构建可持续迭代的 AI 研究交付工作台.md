9.1.1.4 [进阶] 构建可持续迭代的 AI 研究交付工作台
用一个长期 Session 承载复杂研究任务，实时观察 Agent 的工具调用和执行状态，并把每轮结果沉淀为可审阅、可继续优化的完整交付物。
你将构建什么
「研究工作台」接受一个研究目标和若干资料链接，由方舟 Managed Agents 在云端执行长任务。用户能够看到 Agent 正在调用什么工具、当前处理到哪一步，并在 Session 完成后直接审阅完整报告。如果首版报告不够好，用户可以继续提出「补强证据」「增加方案对比」或「重写结论」。系统不会重新创建任务，而是继续向原 Session 发送消息，生成 V2、V3，同时保留旧版本。
最终应用具备以下能力：
接收飞书文档、网页和业务背景；
展示工具调用、阶段消息和 Session 状态；
以 session.status_idle 判断本轮完整输出已经结束；
在同一个 Session 中持续追加优化要求；
保存每轮完整交付物，支持版本切换和导出；
提供当前 Session 的方舟控制台入口；
用户确认后再执行发布等外部写操作。

async function request(path, init = {}) {
const response = await fetch(`${baseUrl}${path}`, {
 ...init,
headers: {
Authorization: `Bearer ${apiKey}`,
"Content-Type": "application/json",
 ...init.headers,
 },
 });
if (!response.ok) {
throw new Error(
`${init.method || "GET"} ${path} 失败:${await response.text()}`,
 );

async function createSession() {
const response = await request("/sessions", {
method: "POST",
body: JSON.stringify({

 }),
 });
const session = await response.json();

}
async function sendMessage(sessionId, text) {
await request(`/sessions/${sessionId}/events`, {
method: "POST",
body: JSON.stringify({
events: [{
type: "user.message",
content: [{ type: "text", text }],
 }],
 }),
 });
}
function textFromEvent(event) {
return event.content
 ?.filter((item) => item.type === "text" && item.text)
 .map((item) => item.text)
 .join("\n") || "";

Serverless 环境使用轮询对账
本地 Node 服务可以持续消费 Event Stream。Serverless 请求不应等待整个长任务，可以使用「快速提交+ 前端轮询 + 服务端对账」：

前端定时调用任务详情接口；
服务端读取 Session 当前状态和事件历史；
Session 仍为 running 时继续等待；
Session 为 idle 时提取本轮最终结果并生成版本。

为中断和重启设计恢复
应用需要保留 Session ID。浏览器关闭或服务重启后，不要重复提交任务，而应：
查询 GET /sessions/{session_id} ；
读取 GET /sessions/{session_id}/events ；
Session 为 running 时继续观察；
Session 为 idle 时恢复最后的完整交付；
对已经处理过的源事件做幂等去重。
保护凭证和外部写操作
ARK API Key 只保留在服务端；
生产环境为每个用户或租户校验任务访问权限；
