3.8.3 流式输出
流式输出通过请求字段 stream=true 启用。服务端使用 SSE（Server-Sent Events，服务器发送事件）持续推送生成片段，客户端可以在完整响应结束前处理正文、思考内容或工具参数；默认的 stream=false 会等待模型生成完成后一次性返回结果。
以下章节覆盖流式请求的启用、事件消费、终态判断和连接管理。完整字段定义以 Chat API、ResponsesAPI 和 Messages API 参考页为准。

throw new IOException("Stream error: " + event.path("error"));
 } else if ("message_stop".equals(eventType)) {
break;
 }
 }
 } finally {
 client.dispatcher().executorService().shutdown();
 client.connectionPool().evictAll();
 }
 }
}

Chat API
完整用量：将请求体字段 stream_options.include_usage 设为 true 。服务端通常在 data: [DONE] 前增加一个 choices=[] 的数据块，其 usage 表示整次请求的 token 用量。
逐块累计用量：将 stream_options.chunk_include_usage 设为 true 。每个数据块的 usage 表示截至当前时刻的累计值；客户端只保留最新值，不得逐块相加。
模型例外：模型 deepseek-v4-1-flash-economy-260910 不受 stream_options.include_usage 控制。该模型默认在带 finish_reason 的数据块中返回 usage ，不额外返回独立的用量数据块。
Responses API
在 response.completed 、 response.incomplete 或 response.failed 终态事件的 response.usage 中读取当前请求的用量。终态前断连且没有返回该字段时，将统计标记为未采集，不记为 0 。
Messages API
Messages 的 usage 是累计快照，不是需要求和的增量：
收到 message_start 时，用 message_start.message.usage 初始化当前快照。该快照包含输入和缓存相关用量；生成刚开始时， output_tokens 通常为 0 。
收到带 usage 的 message_delta 时，用事件中的同名字段覆盖当前快照。不得将 input_tokens 、output_tokens 或缓存 token 与上一快照相加。
收到 message_stop 后，将最新快照标记为本次请求的最终统计。
如果在 message_stop 前断连，只能保留最后一次快照并标记为“未最终确认”；没有收到 usage 时标记为“未采集”，不得记为 0 。
处理连接中断
在正常终态前出现 EOF、超时或网络断开时，已接收内容只是部分结果。客户端应标记部分结果并释放连接；仅在具备幂等策略且业务允许重复生成时重新请求。本文不定义断点续传。
Messages 以 message_stop 收尾，不使用 [DONE] 代替消息终态；结果分类仍由此前 
message_delta.delta.stop_reason 决定。
工作原理
建立连接：客户端发送包含 stream=true 的请求，并为每个并发请求维护独立的 SSE 连接。聚合增量：客户端按所选 API 的事件类型分派数据，再使用该事件声明的索引将片段追加到对应输出项。
判断完成：客户端使用所选 API 的语义终态提交结果；若在终态前断连，则将已接收内容标记为部分结果并释放连接。
