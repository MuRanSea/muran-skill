6.3.3 自托管环境
6.3.3.1 自托管环境概述
本文介绍方舟 Managed Agents 自托管环境（Self-hosted Environment）的适用场景、工作原理和能力边界，帮助你判断是否应该选择自托管环境。
什么是自托管环境
自托管环境将 Agent 的工具执行、文件系统和网络放在企业自己的基础设施，而方舟继续托管模型推理、Agent 编排、Session 管理与事件流。
在当前工具体系中，迁移到企业 Worker 的执行能力是主 Agent 的 bash 、 read 、 write 、 edit 、glob 和 grep 。Web、MCP、多模态工具和自定义工具的执行方不随 Environment 类型变化。方舟负责：
模型推理与 Agent 编排
Session 生命周期管理
事件流持久化与实时推送
Work Queue 的生成与调度
企业负责：
部署 Worker 进程，轮询并执行 Work Item
提供 Sandbox 执行环境（容器、VM 或物理机）
管理企业侧工具使用的文件系统、网络策略和内部资源访问
控制镜像、计算资源和审计
自托管环境继续使用方舟托管的 Agent 编排、Session 生命周期和事件协议，但执行面能力与云环境不同。自托管 Session 不支持通过 resources 挂载 Files、Memory Store 或 TOS 对象，也不能通过Environment 配置依赖包、环境变量、网络策略和产物存储。相关输入、运行时配置与产物转存需要由企业在 Worker 与 Sandbox 中自行准备和管理。
适用场景
以下场景适合使用自托管环境：
敏感代码或文件不能进入平台云沙箱：数据合规要求企业代码、密钥或内部文件不离开企业控制范围。
Agent 需要访问企业内网 API、数据库或代码仓库：工具调用需要访问仅在企业内网可达的服务，无法通过公网暴露。
企业需要控制镜像、网络策略和计算资源：对 Agent 执行环境有定制化要求，需要指定操作系统、预装工具或网络白名单。
企业已有容器、Kubernetes 或 MicroVM 基础设施：希望复用现有集群调度、监控和日志体系。不适用场景
以下场景不建议使用自托管环境：
希望零运维、按需自动拉起 Sandbox：云环境由方舟全托管，无需企业部署和维护 Worker。不具备安全隔离工具执行的能力：自托管环境要求企业自行实现 Sandbox 隔离，否则 Agent 可能越权访问主机资源。
仅需调用少量外部业务函数：如果工具只是调用企业已有的 HTTP API，优先考虑 Custom Tool 或 MCP ，无需部署 Worker。
与云环境的区别
工作原理
方舟控制面与企业执行面的协作流程如下：
业务应用通过 Session API 创建 Session 并发送用户消息。
方舟控制面完成模型推理，生成工具调用并写入 Work Queue。
企业 Worker 轮询 Environment 的 Work Queue，领取 Work Item。
主 Agent 调用 bash 、 read 、 write 、 edit 、 glob 或 grep 时，Worker 在企业 Sandbox 中执行并回传结果。
主 Agent 调用 Web、MCP 或多模态工具时，方舟完成执行；Agent 调用自定义工具时，业务应用完成执行。
工具结果进入方舟控制面，驱动下一轮推理。
任务结束后，Worker 清理执行环境，继续轮询下一个 Work Item。

核心对象
一次任务如何运行
一次自托管任务由业务应用、方舟控制面和企业 Worker 共同完成。业务应用负责发起任务和执行自定义工具，方舟负责模型推理、Agent 编排与任务调度，Worker 负责在企业 Sandbox 中执行主 Agent 的 Bash和文件工具。
业务应用发起任务后，方舟生成 Work Item。Worker 领取 Work Item 并通过 ACK 完成认领。各执行方随后处理工具调用，并将结果回传方舟。Agent 根据结果继续推理或结束任务。
业务应用发起任务：业务应用调用 创建会话 接口，创建绑定自托管 Environment 的 Session。随后调用 发送会话事件 接口，发送 user.message 事件。方舟收到事件后，开始本轮 Agent 编排与模型推理。
方舟生成待执行的 Work：方舟控制面为当前 Session 生成 Work Item，并将其写入该 Environment 的Work Queue。Work Item 用于把 Session 的执行任务交给企业 Worker。
Worker 领取并认领 Work：Worker 调用 长轮询拉取待执行 Work 接口，从 Work Queue 领取 WorkItem。随后调用 认领 Work 接口（ACK），确认由当前 Worker 执行。ACK 成功后，Worker 调用 流式获取会话事件 接口订阅对应的 Session Events，并调用 续租 Work 接口发送心跳
（Heartbeat），保持 Work 租约有效。
各执行方处理工具调用：主 Agent 调用 bash 、 read 、 write 、 edit 、 glob 或 grep 时，Worker 在企业 Sandbox 中执行；调用 Web、MCP 或多模态工具时，由方舟执行；调用自定义工具时，由业务应用执行。
工具结果驱动下一轮推理：各执行方将工具结果回传给方舟。方舟把结果交给主 Agent，继续模型推理。后续如果产生新的工具调用，各执行方继续按上一步的边界处理。
任务结束并清理执行环境：上述过程持续到 Session 进入 idle 或终态。Worker 随后完成 Work Item，清理本次任务使用的企业 Sandbox，并继续轮询下一个 Work Item。
