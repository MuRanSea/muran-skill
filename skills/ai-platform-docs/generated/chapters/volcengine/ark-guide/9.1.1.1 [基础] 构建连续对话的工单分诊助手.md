9.1.1.1 [基础] 构建连续对话的工单分诊助手
本教程面向第一次接触方舟 Managed Agents 的开发者。你将先认识 Agent、Skill、Environment、Session 和 Event 五个核心对象，再以一个售后工单分诊场景跑通完整链路。
完成后，你会得到一个绑定了工单分诊 Skill 的 Agent，并能在 同一个 Session 中连续发送两轮消息：第一轮提交故障现象，第二轮补充新的线索。Agent 会沿用上一轮的上下文继续判断，而不是重新开始。先理解五个核心对象
五者的关系可以概括为：Agent 决定「谁来做、会什么」，Environment 决定「在哪里做」，Session 承载「这一次具体任务」，Events 记录「任务如何一步步发生」。
其中最重要的一点是： Session 不是一次请求，而是一段可持续推进的任务上下文 。每次调用 POST /sessions/{session_id}/events 都是在这个 Session 中追加一个新的回合，而不是重开一次模型调用。你将跑通的场景

你刚才完成了什么
你已经完成了 Managed Agents 的最小闭环：把组织流程写成 Skill，绑定到 Agent，创建 Environment 和Session，通过 Events 发送消息，再以 session.status_idle 判断一轮结束。更重要的是，你没有把第二条要求当成一项新任务，而是复用了原 Session，让 Agent 基于已有上下文继续工作。
下一步可以选择一个方向扩展：
把 CRM、工单或知识库接成 MCP Tool；
给 Session 挂载文件或 Memory；
把 Events 映射成产品中的过程状态；
为高风险工具增加用户确认和幂等控制。
