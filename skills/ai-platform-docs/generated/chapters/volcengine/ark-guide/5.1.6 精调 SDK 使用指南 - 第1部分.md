5.1.6 精调 SDK 使用指南
概述
火山方舟精调 SDK 用于通过代码创建和管理大模型精调任务，适合将训练流程集成到本地或第三方系统，以及开发自定义 Rollout 和奖励函数的强化学习场景。
本文介绍从安装授权、初始化项目、配置训练参数到提交任务和管理产物的操作。强化学习任务还需按场景开发、测试 Rollout / Grader 插件（Plugin），并配置日志和轨迹分析。

通过精调 Skill 使用（推荐）
精调 Skill（ arkcli-train-finetune ）是面向 AI Agent 的大模型精调工作流能力包，将 Ark CLI 与精调 SDK 的能力组织为 Agent 可调用的任务流程。您可以用自然语言描述精调目标，由 Agent 根据需求选择工具并衔接后续操作。需要安装、授权或提交任务时，Agent 会引导您完成必要确认。
精调 Skill 支持以下操作：
准备并创建任务：登录鉴权，查询可训练模型、训练方式、超参数和价格，预览配置、估算费用并提交任务。
准备与管理数据：使用本地文件、TOS 或 Dataset 数据，配置采样并校验格式；衔接数据集 Skill 完成数据集的创建、查询、更新、删除和下载。
自定义强化学习：准备 SDK 环境，配置 Pipeline 与可用资源组，开发 Rollout / Grader Plugin，开展单条、批量及在线测试，配置日志与追踪，并提交调试和正式任务。
观测与管理任务：查询或保存进度、指标、日志及可用轨迹，修改任务信息，执行暂停、恢复、停止和删除。
使用训练产物：按效果指标选择产物、导出到模型仓库，衔接模型管理、支持的部署方式与推理测试。

自动版本检查
从 0.6.0 版本开始，SDK 会在常规 CLI 命令运行前检查是否有新版本，并在发现新版本时提示升级。检查不会自动安装新版本；执行 ark upgrade 才会开始升级。

开发强化学习插件
使用 Plugin 训练前，确认精调 SDK 版本 >= 0.6.2；默认 GRPO 训练要求 SDK 版本 >= 0.7.3。版本不满足要求时，先按 版本升级 更新 SDK，再提交训练任务。
Plugin 用于定义强化学习中的轨迹生成和评分逻辑：
Rollout Plugin：通过 @rollout 装饰器标记，用于实现多轮推理、工具调用等 Agent 执行逻辑。Grader Plugin：用于计算奖励分数。 @single_grader 对单条轨迹评分，平台会将同一样本的 n_samples 条轨迹拆分为独立请求； @group_grader 在一次调用中接收同一样本的多条轨迹，并返回对应的一组分数。
您可以在项目中实现 Plugin 函数，并通过装饰器声明函数类型、元信息和运行配置。未添加相应装饰器的函数不能作为 Plugin 使用。提交任务时，SDK 会校验函数签名和 Pipeline 配置是否完整。装饰器支持的可选参数如下：

Group Rollout 在一次插件调用中生成同一样本的一组候选轨迹，适用于需要共享上下文、复用中间结果或比较组内输出的强化学习场景。
单条轨迹采样（Single Rollout）会针对同一个样本并行执行 num_generations 次，各条轨迹互相不可见。Group Rollout 则只调用一次插件，并在同一次调用中生成 n_sample 条轨迹，因此各分支可以共享中间状态或互相比较。
函数签名
Group Rollout 的函数签名需要增加 n_sample 参数。 n_sample 等于任务中的 num_generations ，由训练引擎传入。
proxy.rollout_client() 和 proxy.async_rollout_client() 会根据装饰器自动返回适用于 Single Rollout 或 GroupRollout 的客户端。只有直接调用底层包装函数时，才需要区分：
Single Rollout： wrap_client_inplace / wrap_async_client_inplace 。
Group Rollout： wrap_responses_client_inplace / wrap_responses_async_client_inplace 。对比项 Single Rollout Group Rollout

def custom_advantage_grader(
 context: PluginContext,
 sample: ChatCompletionSample,
 trajectories: List[Trajectory],
) -> GroupGraderResult:
 rewards = [
 trajectory.extra["reward"]
if trajectory.extra and "reward" in trajectory.extra
else 0.0
for trajectory in trajectories
 ]
import math
 count = len(rewards)
if count > 1:
 reward_mean = sum(rewards) / count
 variance = sum(
 (reward - reward_mean) ** 2 for reward in rewards
 ) / (count - 1)
 reward_std = math.sqrt(variance) + 1e-6
else:
 reward_mean = 0.0
 reward_std = 1.0
 seq_advantages = [
 (reward - reward_mean) / reward_std for reward in rewards
 ]
return GroupGraderResult(
 rewards=rewards,
 status=PluginStatus.SUCCESS,
 error="",
 metrics={},
 seq_advantages=seq_advantages,
 )

OPD 蒸馏
在线策略蒸馏（On-Policy Distillation，OPD）在强化学习流程中引入教师模型的监督信号。学生模型生成轨迹后，教师模型对其提供训练信号。
OPD 适用于同系列模型之间的白盒蒸馏，支持：
为不同轨迹动态选择教师模型，实现多教师路由（Multi-Teacher Routing）。
将任务奖励（GRPO、GAE 或 Custom Advantages）与 OPD 信号组合使用。
为教师模型配置独立于学生模型的上下文，例如评分标准、人工示范轨迹或参考步骤。
跨系列模型和黑盒蒸馏暂不支持。具体的学生模型与教师模型组合、训练方式和申请开通范围以模型支持表及控制台为准。

路由重放（Routing replay）
MoE 模型在采样（Rollout）、策略模型前向计算（Actor forward，重新计算旧策略对数概率）和策略更新（Actor update）三个阶段分别执行专家路由。路由结果不一致时，训练使用的对数概率会偏离实际采样策略，产生离策略偏移（off-policy）。路由重放（R3）记录采样阶段的专家路由，并在后续计算中复用，以减小对数概率差异、提高训练稳定性。
单轮语义
路由记录对应每次前向计算中输入位置的专家分配。对于包含 n_input 个提示 Token 和 n_decode 个生成 Token 的单轮采样：
预填充（Prefill）阶段记录 n_input 行路由。
前 n_decode - 1 个生成 Token 会在后续解码步骤中作为输入，因此各记录一行路由。
最后一个生成 Token 没有再次作为输入，不会产生路由记录。
因此一轮可记录并重放的路由行数为 n_input + n_decode - 1 。
多轮语义
多轮对话中，R3 维护与 input_ids 逐位置对齐的全局路由缓冲区。每轮追加实际执行的路由，并在本轮最后一个、尚未产生路由记录的 Token 位置写入标记值 -1 。
重放时：
历史位置包含有效专家 ID 时，强制复用已记录的路由。
-1 位置和本轮新增提示没有历史路由记录，继续使用模型原生的 top-k 门控。
R3 仅重放实际执行过的路由，不为尚未参与前向计算的 Token 构造路由。
启用与支持范围
建议直接使用最新 SDK；最低版本要求为 Single Rollout >= 0.6.2、Group Rollout >= 0.7.3。Seed 2.0 / 2.1 模型在 GRPO、GRPOLoRA、PPO、OPD（仅 sampled token）和 OPDLoRA 训练方式下可开启路由重放；模型版本须支持对应训练方式，参见 模型支持表 。

PPO 评价模型上下文解耦（critic decouple）
