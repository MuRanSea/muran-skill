使用说明
深度思考
深度思考开关：通过 thinking 参数控制模型是否开启深度思考模式，默认开启思考。
调节思考长度：通过 reasoning_effort 参数调节思考长度，支持 none 、 minimal 、 low 、medium 、 high 、 xhigh 、 max 七种模式，默认开启 high 模式。
输出思考内容摘要：默认开启 thinking summary 能力，不会输出模型原始的思考内容，会返回模型思考内容摘要和思考内容加密原文。建议全量回传，服务端会基于场景判断是否会丢弃思维链内容。具体见回传思考内容加密原文 。 
Chat API：回传 encrypted_content 字段。
Responses API：推荐使用 previous_response_id 回传。
多模态理解
Doubao-Seed-Evolving 面向 Coding 和 Agent 场景，支持图片、视频、文本理解，未支持音频理解及视频中的音频理解。
图片理解：通过 detail 参数控制模型理解图片的精细度，支持 low 、 high 、 xhigh 三种模式，默认值为 high 。不同模式支持的单图 token 范围和图片像素区间如下。教程参见图片理解 。视频理解：通过 fps 控制视频理解的精细度，教程参见视频理解 。
Files API 上传：如果图片、视频、文档文件超过 10 MB，建议使用 Files API 上传，通过 File ID 方式进行多模态理解。
工具调用
工具调用场景开启深度思考后，为给出更详尽准确的回答，将不会直接丢弃思维链内容，思维链内容可能参与后续轮次推理，输入 token 会增加。建议全量回传思考内容，服务端会基于场景判断是否会丢弃思维链内容。具体原理及请求示例参见工具调用场景 。

上下文缓存
利用缓存机制复用计算结果，避免模型对相同内容的重复处理，降低 token 成本。具体使用见上下文缓存。
隐式缓存：自动模式，用户无需做额外配置。系统会自动识别请求中的公共前缀并进行缓存，但不保证缓存命中。支持 Responses API、Chat API，默认开启。
显式缓存：需要显式创建缓存，但能实现更高的缓存命中率。支持 Responses API，提供前缀缓存、Session 缓存。
