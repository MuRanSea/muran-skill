回传思考内容：按模型选择支持的回传方式。对需要回传思考内容加密原文的模型，必须原样回传思考内容加密原文。

核心机制：思考内容回传
为什么需要回传思考内容
在 Agent 场景中，一个任务通常会经历多轮“推理 -> 调用工具 -> 等待结果 -> 继续推理 -> 调用工具”，工具结果返回后，模型需要继续在该推理链路上把后续步骤做完。
如果不回传思考内容，会有以下影响：
推理连续性会被打断：工具结果返回后，模型只能根据可见对话文本重新构建上下文。对于复杂任务这些隐含的中间判断无法被完整还原，容易出现推理衔接不顺或逻辑断层的情况。
多步执行稳定性下降：由于缺少中间推理状态，模型可能重复做已做过的推导，或者在下一步采用与前一步不一致的假设，导致任务执行跑偏、步骤不稳定，影响结果的一致性与可复现性。
整体成本上升：回传的思考内容会与 tool result 一起参与缓存，更容易命中 Prompt Cache。对包含多次工具调用的场景来说，缓存命中意味着减少重复 token 消耗，从而降低整体成本。
回传方式与支持模型
方舟大模型的思考内容回传方式分为两类：
回传思考内容原文（明文） ：将响应中的思考内容原文直接拼回下一轮请求。
回传思考内容加密原文：将响应中的加密原文原样拼回下一轮请求。
两类回传方式支持的模型不同，具体参见 推荐使用方式 。
关键规则
思考内容加密字段要求原样、完整回传。任何篡改或截断都会返回 Invalid signature 错误。不回传思考内容加密原文不会触发报错，但会影响推理效果。
思考内容加密字段优先级高于思考内容摘要：同时传入时，明文摘要会被忽略。
输出思考内容部分计费会按原始思考内容 token 计算，如果不回传思考内容加密原文，已付费的思考内容不仅没有起到效果，还可能会导致推理效果下降。
