4.5 在线推理（TPM 保障包）
在线推理（TPM保障包） 使用平台预留资源，保障模型请求吞吐量达到指定TPM（Tokens Per Minute，每分钟处理的Token总量），目前拥有最高优先级。同时，溢出部分使用 在线推理（常规） 处理 token，并溢出 token 按降级后的推理模式计费。本文介绍在线推理（TPM 保障包） 的主要优势、支持的模型和使用流程。
主要优势
更低的延迟：相比 在线推理（常规） ，在线推理（TPM 保障包） 的延迟更低，通常低 1/3 - 1/2。更高的吞吐量：通过预留资源保障指定TPM吞吐量，同时支持超过默认限流额度的并发请求数。更强稳定性：提供高资源确定性保障，在保障范畴内不会命中异常流量熔断、限速策略，持续保障业务服务可用性。
弹性伸缩：后付费TPM保障包，支持定时调整TPM保障包数量，贴合业务波峰波谷，提升资源利用率并降低成本。
灵活组合： 
组合使用后付费与预付费保障包：在业务高峰时段，您可以将按小时（后付费）与按天（预付费）的保障包叠加使用，以更好地匹配流量峰谷，从而避免资源浪费。
组合使用保障包与常规在线推理：系统会优先消耗您的保障包额度。当请求超出额度后，将自动降级为常规在线推理模式。这种方式既能为可预估的流量提供性能保障，也能为临时流量高峰提供缓冲。请注意，超出部分的流量会计算在默认限流额度中。
适用场景
追求更低延迟，更高并发的高需业务。
可预估流量大小的高流量业务。
无法接受偶发的资源紧张报错的业务。
注意
TPM 保障包保障输出 Token 生成速率（TPOT，Time Per Output Token），不同模型能达到的延迟水平存在差异。
TPM 保障包不保障首 Token 延迟（TTFT，Time To First Token），但通常 TTFT 优于公共资源池。

1 创建推理接入点
TPM 保障包需与推理接入点（Endpoint，调用推理服务的网络入口，简称 接入点）绑定后使用，即在创建或编辑接入点时，购买或调整TPM保障包。
访问 创建推理接入点 ，按页面引导填写。注意选择接入模式为 TPM保障包。 
强烈推荐打开右上角 创建说明 开关，帮助您了解每个配置项的使用场景和含义。
根据业务需求使用 TPM计算器 （ 选择接入模式为 TPM保障包 后，在右侧 创建说明 中可见）预估需购买的输入和输出额度，并 申请配额 。
详细抵扣说明见 额度抵扣说明 。
创建完成后进入 调度中 状态，当状态变成 健康 后，可正常调用。

推理接入点默认会创建在 default 项目下，如果您希望在其他项目下创建，请在导航栏左下角切换项目。

抵扣逻辑
不同模型，请求的不同输入输出长度，抵扣
TPM 额度的速度不同，需按抵扣系数计算购
买的TPM。
抵扣额度计算公式 
抵扣输出额度 = 输出 token * 抵扣系数
抵扣输入额度 = 输入 token * 抵扣系数
TPM 计算器
可通过 TPM 计算器 查看相应的抵扣系数，并
估算实际需要购买的可抵扣 TPM。
入口：创建接入点 ，完成模型选择，并选
中 TPM 保障包，在右侧创建说明窗格中展
示。
抵扣示例
购买的某模型的 TPM 信息： 
额度：输入 1000k TPM，输出 200k TPM。
抵扣系数：输入 10k token 时抵扣系数为
1，输出 1k token 时抵扣系数为 4。
当输出 TPM 达到 50k token 时，
50k * 4 抵扣系数 = 200k token ，TPM 输出额度
达上限。

定时弹性：您可以设置在某一时间节点（可精确到分钟）后将TPM保障包的输入TPM（每分钟可处理的输入Token总量）和输出TPM（每分钟可生成的输出Token总量）调整到您所需的新的值。
周期性弹性：您可以「按天重复」、「按周重复」或「Cron表达式」来设置时间规则，TPM保障包的输入TPM和输出TPM将会在您所设置的时间节点后调整到您所需的新的值。

使用限制
支持通过 Chat API 调用模型。 
不支持结构化输出(beta) （ response_format.type 无法设置为 json_object 、 json_schema ）。不支持视频输入。
不支持 Context Create API 、 Responses API 。
当接入点请求超过保障包额度时，自动切换为普通在线推理模式，以 按Token付费 模式收费。模型请求的输入范围符合下方条件。如不符合，无法使用 TPM 保障包，请求返回的 service_tier 字段为default ，即普通在线推理模式，不扣减保障包额度。 
Doubao 模型，输入长度 (0, 128k]。
DeepSeek 模型，输入长度(0, 64k]。
