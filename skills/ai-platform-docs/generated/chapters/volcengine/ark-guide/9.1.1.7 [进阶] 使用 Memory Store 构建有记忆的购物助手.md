9.1.1.7 [进阶] 使用 Memory Store 构建有记忆的购物助手
本教程演示如何使用方舟 Managed Agents 的 Memory Store（记忆存储） 能力，构建一个能记住客户购物偏好的个人购物助手。跨会话保留的记忆让 Agent 无需在每次对话开始时重复询问尺码、预算、材质忌讳等信息，从而提供真正个性化的服务。
场景说明
大多数销售助手每次对话都要从头开始。顾客告诉助手尺码、预算和不喜欢的材质，但下次顾客回来时，这些信息全都不见了，顾客不得不重复一遍，整个体验缺乏个性化。
Managed Agents 提供了开箱即用的记忆能力：Memory Store。它是一个由平台托管的持久化容器，Agent 可以在多次会话之间通过后端应用层 API 调用读写用户信息，从而记住用户。
你将构建什么
一个 Memory Store，用于保存单个客户的购物偏好。
一个配置为读写该 Memory Store 的购物 Agent。
两个独立的 Session，演示记忆如何跨会话延续。
一种从后端应用检查和初始化记忆的模式。
记忆如何工作
Memory Store 对 Agent 呈现为一个可读的文件目录，挂载在 Session 运行沙箱的 /mnt/memory/{storename}/ 路径下。应用程序可以通过 API 对相同的文件进行完整的读写：把已知信息预填到 MemoryStore、审核 Agent 写入的内容，或将所有内容导出到自有系统。

注意
Memory Store 采用文件挂载语义而非上下文注入语义。挂载后记忆以只读文件出现在沙箱 /mnt/memory/<store-id>/ 子目录下，平台不会把内容自动塞进模型上下文。因此必须在 System Prompt或 Session instructions 中明确指示 Agent 「先执行 ls -R /mnt/memory 找到并读取全部记忆文件」，否则 Agent 用顶层通配符匹配不到子目录里的文件，会误判「没有记忆」。
