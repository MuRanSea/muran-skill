6.6 高级能力
6.6.1 Multi Agent
Multi Agent（多智能体协作）是方舟 Managed Agents 提供的进阶能力，属于 Agent 的能力扩展之一：允许一个 Agent（协调器）将任务委派给其他 Agent（子智能体）执行，实现多智能体之间的分工协作。通过专业化分工和并行执行，提升复杂任务的处理效率和输出质量。
本文介绍如何为 Agent 配置和使用 Multi Agent。
Multi Agent 配置字段
multiagent 字段的完整结构（ type / agents[] / agents[].type / agents[].id / agents[].version ），请参见 创建智能体 API 中的 multiagent 参数说明。
说明
配置了 Multi Agent 的 Agent（协调器）不能再被选作其他 Agent 的子智能体，避免循环调用。准备工作
开始前你需要：
已创建的 API Key：配置为环境变量 ARK_API_KEY ，详情请参见 API Key 管理 。
已创建的 Agent：详情请参见 定义 Agent 。
已创建的 Environment：详情请参见 配置云环境 。
本章节示例的 Base URL 与鉴权方式详情请参见 Base URL 及鉴权 。
在配置 Multi Agent 之前，你需要：
已经创建好所有需要用作子智能体的 Agent，并记录它们的 Agent ID。
每个子智能体已经配置好各自的模型、系统提示词、Skills、Tools 等。
准备好作为协调器的 Agent。
配置 Multi Agent
控制台方式
进入 Agent 管理页面 。
选择一个将作为协调器的 Agent，点击「编辑」（或新建一个 Agent）。
在左侧「04 能力扩展」区域，找到「Multi Agents」，点击「添加」。
从列表中选择已创建的子智能体，可添加多个并调整顺序。
在系统提示词中说明每个子智能体的专长和使用场景。
点击「保存」。
API 方式
创建或更新 Agent 时，传入 multiagent 配置即可开启 Multi Agent。

启动协调器 Session
完成协调器 Agent 配置后，使用协调器的 agent_id 创建 Session 并发送任务：
通过 创建环境 创建云托管 Environment，或复用已有 Environment。
通过 创建会话 创建绑定协调器 Agent 的 Session。协调器委派任务时，系统会为对应的子智能体创建独立子线程。
通过 流式获取会话事件 建立 SSE 连接，并等待服务端返回 : ready 。
通过 发送会话事件 发送首个 user.message 事件，启动协调器。仅创建 Session 不会触发任务。工作方式
会话线程机制
Multi Agent 基于「会话线程」机制实现上下文隔离：
主线程：协调器所在的主会话线程，与用户直接交互。
子线程：每个被委派的子智能体在独立的子线程中运行，拥有独立的对话历史。
线程持久化：子线程在整个会话生命周期内持久存在，协调器可以向同一个子智能体发送后续消息。委派流程
用户向协调器发送任务。
协调器分析任务，决定是否需要委派、委派给谁。
系统创建子线程，启动子智能体。

系统提示词建议
协调器的系统提示词直接影响任务拆分和委派的质量。以下是一些编写建议：
明确子智能体的能力边界
清晰描述每个子智能体的专长、擅长领域和不擅长的事情，帮助协调器做出正确的委派决策。定义协作流程
明确任务流转的方式，比如是否需要串行、是否可以并行、什么情况下需要复审等。
观察执行过程
Multi Agent 的执行过程可以通过事件流观测：
你有以下团队成员可以调用：
【代码审查员】
- 专长：代码质量审查、架构设计评估、安全漏洞检测
- 输入：完整的代码文件或代码片段
- 输出：审查报告，包含问题列表和改进建议
- 不擅长：功能开发、编写新代码
【测试工程师】
- 专长：单元测试编写、测试用例设计、覆盖率分析
- 输入：代码文件 + 功能需求描述
- 输出：测试代码文件 + 测试报告

注意事项
版本锁定
协调器创建时会锁定子智能体的版本号。后续子智能体更新版本后，协调器不会自动升级，需要手动更新协调器配置才能使用新版本的子智能体。
嵌套限制
Multi Agent 目前只支持一层委派：协调器 → 子智能体。子智能体不能再配置 Multi Agent 作为下一级协调器，即不支持深度大于 1 的嵌套调用。
数量限制
单个协调器最多可以配置 20 个不同的子智能体。但协调器可以调用同一个子智能体多次，产生多个并行的子线程。
资源与计费
每个子线程独立消耗模型 token 和沙箱资源。
子智能体的费用按各自的模型和使用量分别计费。
沙箱环境和文件系统在协调器和子智能体之间共享。
具体计费规则请参考方舟 Managed Agents 的 计费说明 。
观测维度 说明
主线程事件 协调器的思考、工具调用、子智能体委派决策

线程状态 各子线程的运行状态（运行中、空闲、已终止）
