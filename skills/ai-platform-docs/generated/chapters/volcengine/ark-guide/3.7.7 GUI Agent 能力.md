3.7.7 GUI Agent 能力
本文介绍如何使用方舟接口调用模型，构建 GUI Agent 应用，实现基于界面截图和提示词解析出可执行的动作意图。本文提供两种用法：GUI Agent 输出离散动作、纯 Grounding 单步定位，其中调用使用原生OpenAI SDK（不传 tools），动作解析使用 ui-tars 官方解析器。
说明
方舟平台的新用户？获取 API Key 及 开通模型等准备工作，请参见 快速入门 。
支持模型
Doubao Seed 系列模型。
任务流程：观察-决策-动作的回环
任务流程图
让模型像人一样操作图形界面：看屏幕截图 → 想下一步做什么 → 动手执行 → 再看新的屏幕……如此循环，直到任务完成。
任务结束：输出纯文本且不含 <seed:tool_call> 时，视为任务完成并结束回环，该纯文本即为最终答案。
1. 观察（截图） 把当前屏幕 PNG 编码成 image_url，连同任务描述发给模型
2. 决策（模型输出） 模型在 message.content 里产出<seed:tool_call> 动作块...
3. 解析 从<seed:tool_call> 里解析出：动作名 + 参数 + 0-1000 相对坐标
4. 执行 把动作打到真实设备（点击/键入/或执行一段代码）
再截一张图，回到 步骤1，直到模型输出结束。Text is not SVG - cannot display
本文给到的两种用法：
GUI Agent（方式一） ：会执行上述步骤1-4，其中步骤4会解析成可执行动作，未将动作打到真实设备。
纯 Grounding（方式二） ：只执行上述步骤1-3，输出 click 坐标。
关键约定
不传 tools
调用 chat.completions.create 时 不要 传 tools 参数。
原理：模型经训练会按 system prompt 里的动作说明，把动作块 **直接写进 ** message.content ，形如：思维链在独立字段 message.reasoning_content （ content 里没有 <think> 外壳）。若你传了 tools ，会走 OpenAI function calling，输出格式完全不同，与本指南不兼容。
坐标转换
所有点击 / 拖拽类坐标都是 0–1000 的相对坐标，与截图分辨率无关。
原理：模型输出 <point>x y</point> ，其中 x、y 都在 [0, 999] 归一化空间内。相对坐标映射回真实像素的公式：

动作解析
动作解析直接调 ui-tars 包的官方解析器，返回官方结构 [{"function":..., "parameters":...}] ，按出现顺序排列，自动兼容多个 <seed:tool_call> 块、单块多 <function> (串行 / 并行 / 多动作预测)。注意
返回空列表(没有任何 <function> 动作块)：表示模型以纯文本收尾，交互结束。

def call_ark(client, model: str, messages: list, max_tokens: int = 2048,
 temperature: float = 0.7) -> ModelReply:
"""调用 Ark 的 chat.completions,**不传 tools**。"""
 resp = client.chat.completions.create(
 model=model,
 messages=messages,
 temperature=temperature,
 max_tokens=max_tokens,
 )
 choice = resp.choices[0]
 msg = choice.message
return ModelReply(
 content=msg.content or "",
 reasoning_content=getattr(msg, "reasoning_content", None) or "",
 finish_reason=choice.finish_reason,
 usage=resp.usage,
 )

def extract_point(value: str) -> tuple[float, float] | None:
"""从 `"<point>x y</point>"` 里取出 (x, y) 的 0–1000 相对坐标;取不到返回 None。"""if not isinstance(value, str):
return None
 inner = value.replace("<point>", "").replace("</point>", "").strip()
 parts = inner.split()
if len(parts) == 2:
try:
return float(parts[0]), float(parts[1])
except ValueError:
return None
return None
def rel_point_to_pixel(point: tuple[float, float], image_size: tuple[int, int]) -> tuple[int, int]:
"""把 0–1000 相对坐标映射回真实像素坐标。"""
 x, y = point
 w, h = image_size
return round(x / 1000.0 * w), round(y / 1000.0 * h)

不跑回环，只做单步定位：一条指令 + 一张截图 → 模型输出一个 <seed:tool_call> 的 click 动作，坐标是 0–1000 相对坐标，按截图宽高换算成像素，即定位到目标元素。示例脚本是批量评测， 用一批带标注的样本跑分做接入对齐校验，单样本处理在 process_item 。
与 GUI Agent 的本质区别：Grounding 是单步定位，输入端就给定了截图、输出端只给一个坐标, 没有多轮回环、不判结束、也不真正执行动作。它回答的是给定意图,目标元素在屏幕上的哪个坐标, 而不是自主一步步把任务做完。拿到坐标后要不要点、点了之后怎么办，由用户自己的逻辑决定。
