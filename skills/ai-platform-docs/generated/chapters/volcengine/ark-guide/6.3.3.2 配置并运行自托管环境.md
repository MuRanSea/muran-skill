6.3.3.2 配置并运行自托管环境
本文介绍如何从零配置自托管环境（Self-hosted Environment），选择 Go、Python 或 Java SDK 启动Worker，并完成一次完整的 Session 工具执行。
你将完成什么
在控制台创建 self_hosted 类型的环境
生成并安全保存 Worker 凭证
选择 Go、Python 或 Java SDK，在企业主机启动 Worker
创建绑定自托管环境的 Session
发送用户消息，让 Agent 在企业主机执行工具
验证工具执行结果、Session 终态和 Worker 状态
核心概念
工作流程
以下是自托管环境端到端的工作流程：
企业管理员在控制台创建自托管 Environment，生成 Worker 凭证。
企业运维人员在企业主机启动 Worker，Worker 开始轮询 Work Queue。
业务应用使用业务 API Key 创建 Session 并发送用户消息。
方舟控制面生成 Work Item，Worker 领取并 Ack。
Worker 在企业 Sandbox 中执行工具调用（Bash、文件读写、自定义工具）。
Worker 将 Tool Result 回传方舟，驱动下一轮推理。
重复步骤 5-6，直到 Session 进入 idle 或终态。
Worker 完成 Work Item，继续轮询。
前置条件
开始前，请确认以下条件已满足：
已开通 Managed Agents 服务，并已创建 Agent（参见 快速入门 ）
概念 说明
Environment Agent 运行时配置， type 为 self_hosted 时表
示自托管环境
Worker 企业部署的进程，轮询 Work Queue 并在企业
Sandbox 中执行工具调用
Work Item 方舟为需要工具执行的 Session 生成的任务项，
Work ID 与 Session ID 一致
Environment Key
Worker 专用的凭证，仅能 Poll/Ack 指定
Environment 的 Work Item，不能创建 Session 或
调用模型
准备一台企业管理的 Linux 主机或隔离容器，具备以下条件： 
/bin/bash 可用
/workspace 目录可写
已选择一种 Ark Runtime SDK，并按对应仓库 README 准备运行环境：Go 、Python 或 JavaWorker 主机能够通过出站 HTTPS 访问方舟 API（ https://ark.cn-beijing.volces.com/api/v3 ），无需开放入站端口
准备业务 API Key（用于创建 Session，由业务应用持有）
准备 Worker 凭证（将在步骤 2 中生成，由 Worker 主机持有）
注意
业务 API Key 和 Worker 凭证是两种独立的凭证，职责不同：
业务 API Key 用于创建 Session、发送消息和订阅事件，由业务应用持有，不能放到 Worker 主机或 Agent 工作目录
Worker 凭证（Environment Key）用于 Poll/Ack Work Item，由 Worker 主机持有，不能用于创建 Session 或调用模型
两种凭证混用会导致权限越界或功能异常。

第 2 步：生成 Worker 凭证
进入 Environment 详情页的"凭证与接入"页签，点击"生成凭证"：

注意
Environment Key 仅在生成时展示一次。如果丢失，需要吊销已有凭证并重新生成。建议每台Worker 主机使用独立凭证，便于按主机轮换、吊销和审计。
配置 Worker 主机的环境变量：
在 Worker 主机上， ARK_API_KEY 应填写 Environment Key。该凭证只能 Poll/Ack 当前 Environment 的Work Item，不能创建 Session、调用模型或访问其他 Environment。

private static String requiredEnv(String name) {
String value = System.getenv(name);
if (value == null || value.isEmpty()) {
throw new IllegalArgumentException(name + " is required");
 }
return value;

private static String envOrDefault(String name, String defaultValue) {
String value = System.getenv(name);
return value == null || value.isEmpty() ? defaultValue : value;
 }

Work Items 可按 Session ID 找到本轮 Work Item，状态流转

需要扩容时，优先启动多个 Worker 进程或 Pod，并为每个实例设置独立的 MA_WORKER_ID 。不要让多个 Worker 共享同一个 Session 工作目录。
每 Session 独立 Sandbox
适用于 Kubernetes 每 Session 一个 Pod。Poller 负责领取 Work Item 并创建 Pod，Pod 内调用 SDK 的 HandleItem / handle_item 负责该 Work Item 的完整生命周期。
注意
Environment Key 应通过 Kubernetes Secret、Secret Manager 或等价机制挂载，不能明文写入 PodSpec、镜像、工作目录或日志。Worker 在执行 bash 等 Agent 工具前，应清除包含凭证的环境变量。
