6.6.1 编排 Multi Agent
当一次任务需要代码审查、测试设计等不同角色共同完成时，可以使用 Multi Agent。主 Agent（MainAgent）负责拆分任务、选择子 Agent（Subagent），并把各角色的结果汇总成最终答复。
本文以评审一个 Python 登录接口为例。你将为主 Agent 配置代码审查员和测试工程师两个固定成员，再创建 Session、提交评审任务，并通过 Thread 查看各成员的执行过程。开始前，准备 API Key、模型 ID、一个可用的 Environment，以及两个成员 Agent 的 ID 和版本号。
选择协作模式
方舟支持 multiagent_20261001 和 coordinator 两种 Multi Agent 配置。先根据任务是否需要持续协作、跨层派发和运行时角色选择配置，再准备子 Agent。
multiagent_20261001 模式
multiagent_20261001 适合多个角色在独立 Thread 中持续协作，或需要子 Agent 继续派生和派发任务的场景。它遵循以下规则：
子 Agent Thread 创建后会保留在当前 Session 中，可以继续接收任务，也可以单独中断或归档。目标 Thread 接受任务后，派发方可以继续处理自己的工作，不需要等待。
一个 Agent 可以向同一 Session 中已有的其他子 Agent Thread 派发任务，包括同层或不同层的Thread。派发方不会直接收到目标 Thread 的执行结果。
子 Agent 的结果始终异步回投给创建它的父 Thread，而不是最近一次派发任务的 Thread。父 Thread处于 idle 时，结果会唤醒它；父 Thread 仍在运行时，结果会排队等待处理。
只要还有 Thread 正在运行，Session 就会保持 running 。所有 Thread 都不再运行后，Session 才会进入 idle ；此时仍需根据 stop_reason 判断任务已经结束，还是正在等待外部操作。

创建 Session
一个 Session 承载一次多智能体任务。主 Agent 和每个子 Agent 分别使用独立的 Thread：每个 Thread 都有稳定的 session_thread_id ，并独立保存消息和推理上下文。 parent_thread_id 记录创建关系：Main Thread 返回 null ，子 Agent Thread 返回创建它的父 Thread ID。
同一 Session 中的 Thread 共享 Environment、Sandbox、文件系统和已绑定的 Vault 凭据，但不会自动共享对话历史。一个 Thread 写入文件后，其他 Thread 可以读取该文件；需要同时传递结论时，子 Agent 还应回传文件路径和摘要。
