8.1.1.5 [基础] 在豆包工作中使用 Managed Agents
将已在火山方舟中构建好的 Agent 接入豆包工作后，企业员工可以自行添加，企业管理员也可以在方舟控制台发布或在豆包工作后台统一分发。你无需重复开发应用入口，即可复用豆包工作和飞书的对话、任务过程展示与产物交付能力。
场景说明
你已经在火山方舟中完成 Agent 的开发和调试，希望在豆包工作中使用，或者把它分发给其他企业员工，而不是再开发一套对话页面、任务列表和流式输出界面。
根据你的角色选择一条接入路径，无需同时执行两条：
管理员的两条添加方式任选其一：控制台发布会在表单中完成豆包授权和豆包/飞书配置；后台添加需要单独准备 API Key。
豆包工作的伙伴通用操作参见 在豆包工作中使用伙伴和小队 。本文中的“员工自行添加”面向已购买豆包团队订阅或企业订阅、并已开通方舟 Agent 接入功能的企业，不适用于豆包个人版。

概念 说明
Managed Agents 火山方舟提供的托管 Agent 运行框架，负责
Agent 配置、会话、工具调用和运行环境。
Agent 可复用的智能体配置，包含模型、系统提示词、
技能和工具。豆包工作导入的是这项配置。
渠道 方舟 Managed Agents 中用于把 Agent 发布到豆
包工作、飞书等外部入口的配置。
资源项目（Project）
方舟资源的隔离边界。API Key 只能访问所属项
目内的资源，后台添加时 Key 需与 Agent 同项
目。
API Key 连接方舟账号时使用的鉴权凭证。它属于敏感信
息，泄漏后可能造成资源越权访问和费用损失。
前置条件
已开通火山方舟 Managed Agents，详情参见 概述 。
已在方舟中创建并调试 Agent。首次使用时，可参见 快速入门（控制台） 。
员工自行添加时，你已登录豆包工作，所在企业已购买豆包团队订阅或企业订阅、已开通方舟 Agent接入功能，并且你具备在 Agent 所在项目中创建 API Key 的权限。
管理员统一分发时，企业管理员已获得 企业管理后台 的智能体管理权限，并具备在方舟控制台 渠道 中发布 Agent 的权限；使用后台添加方式时，Agent 开发者还需要提供目标 Agent 和同一项目下的专用 API Key。
待导入 Agent 不需要登录或授权第三方服务即可完成基础任务。如果 Agent 使用的第三方服务需要授权，先完成相应服务的登录或授权。
说明
当前只支持接入基于 Managed Agents 开发和配置的 Agent，不支持直接导入任意已有 Agent 服务。
警告
API Key 可以访问所属项目中其权限范围内的资源。建议使用独立项目和专用 API Key，避免与其他应用共享凭证。如果 Agent 开发者和企业管理员不是同一人，使用企业批准的密钥管理工具交接 API Key，不要通过群聊、工单或截图传递。
路径一：员工自行添加
企业员工可以把自己在方舟中维护的 Agent 加入豆包工作。添加后，工作伙伴默认仅本人可用。第 1 步：准备 Agent 和 API Key
在方舟 Managed Agents > Agents 中打开目标 Agent，检查配置并运行一次测试任务。
确认 Agent 所在项目，在 API Key 管理 中创建专用 API Key。
记录 Agent 名称，并安全保存 API Key。
注意
API Key 必须与 Agent 位于同一项目，否则列表中不会出现目标 Agent。
概念 说明
工作伙伴 豆包工作中的 Agent 使用入口，可以由员工自行
添加，也可以由管理员统一提供。
可用范围 管理员分发时使用的访问范围，决定哪些企业员
工可以看到并使用工作伙伴。
第 2 步：导入 Agent
打开豆包工作，单击左侧 插件·技能·伙伴，切换到 工作伙伴 页面，再单击右上角 + 创建 > 接入火山方舟 Agent。
填写 API Key，选择目标 Agent 并完成添加。
第 3 步：在豆包工作中使用
打开 新工作任务，在输入框中输入 @ ，搜索并选择刚添加的伙伴。
发送测试任务，检查回复、任务状态和产物。
例如，数据分析 Agent 可以使用以下任务：
汇总这份销售数据中的主要变化，列出三个异常指标，并给出下一步核查建议。
第 4 步：按需在飞书中使用
在工作伙伴详情中选择 飞书对话，按指引完成添加或授权。
在飞书中发送测试任务，核对工作伙伴和授权账号。
注意
豆包工作与飞书中的会话入口可能不同。不要假设两端共享同一个可见会话列表。
路径二：管理员统一分发
管理员可以选择以下任一方式分发 Agent。控制台发布在表单中完成豆包授权和豆包/飞书配置；后台添加需要单独准备 API Key。两种方式发布后都需要确认伙伴的可用范围。
方式一：在方舟控制台发布
打开方舟控制台 Managed Agents，进入 渠道，单击 添加。
按表单指引完成 3 步配置，每一步完成后单击 下一步： 
完成豆包授权。
补充豆包和飞书配置。
选择 Agent 及其配置。
按表单完成发布。发布后如需调整伙伴信息或可用范围，在豆包工作 企业管理后台 > 伙伴&小队管理中处理。首次发布只选择测试成员，验证通过后再按企业发布流程扩大范围。
打开豆包工作 新工作任务，输入 @ 搜索目标伙伴，发送测试任务验证。
方式二：在豆包工作后台添加
第 1 步：准备 Agent 和 API Key
Agent 开发者在方舟 Managed Agents > Agents 中测试目标 Agent。
在 Agent 所在项目的 API Key 管理 中创建企业集成专用 API Key。
如果企业管理员不是 Agent 开发者，使用企业批准的密钥管理工具交接 API Key。

注意
不要与个人调试或其他应用共享该 API Key，以免撤销访问时影响其他业务。
第 2 步：连接方舟账号
打开豆包工作 企业管理后台 > 伙伴&小队管理。
单击 添加 > 接入火山方舟 Agent。
填写 API Key，选择目标 Agent。
第 3 步：设置范围并发布
设置工作伙伴的名称、说明和 可用范围。
首次仅选择测试成员或测试部门，检查后发布。
注意
可用范围过大会让仍在调试的 Agent 直接出现在企业员工的工作伙伴列表中。首次发布只选择测试成员；验证通过后，再按企业发布流程扩大范围。
验证分发结果
使用测试成员账号打开 新工作任务，在输入框中输入 @ ，搜索并选择目标伙伴。
发送测试任务，检查回复、任务状态和产物。
使用范围外账号打开 新工作任务，确认在 @ 搜索结果中找不到目标伙伴。
确认飞书入口
飞书入口取决于添加方式：
通过方舟控制台发布：表单中已完成豆包和飞书配置，企业员工无需额外操作即可在飞书中使用同款伙伴。
通过豆包工作后台添加：在工作伙伴详情中选择 飞书对话，按指引完成添加或授权。
注意
豆包工作与飞书中的会话入口可能不同。不要假设两端共享同一个可见会话列表。
警告
只在豆包工作的方舟账号连接窗口中填写 API Key。不要把 API Key 填进 Agent 的系统提示词、环境变量说明、工作伙伴介绍或对话消息；这些内容可能进入运行上下文或被其他人看到。
验证结果
完成所选路径的检查，并满足公共检查项，说明基础接入链路已经跑通：
员工自行添加：在 新工作任务 中输入 @ 后，可以搜索并选择目标伙伴。
管理员统一分发：管理员可以在方舟控制台 渠道 或豆包工作后台找到目标 Agent；测试成员可以在 新工作任务 中通过 @ 选择目标伙伴，范围外成员无法搜索到它。
公共检查：发送任务后可以看到回复和任务状态变化，任务执行过程中没有鉴权或工具调用错误；Agent 生成文件时，豆包工作可以展示并打开对应产物。
计费说明
从豆包工作、飞书侧发起的调用支持基于飞书 AI 包扣费，不产生方舟侧账单。
