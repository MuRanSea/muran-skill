7.7 tos-fsp
7.7.1 tos-fsp 概述
本文主要介绍 tos-fsp 的各项特性，帮助您全面了解 tos-fsp 的使用方法。
功能说明
tos-fsp 是对象存储 TOS 提供的 Windows 挂载工具，将 TOS 存储桶或存储桶内指定前缀映射为 Windows盘符，供资源管理器以及支持通过 Windows 文件路径访问且不依赖完整 NTFS 语义的应用访问 TOS 数据，无需在每个应用中单独集成 TOS SDK。
应用场景
通过 tos-fsp 生成的挂载盘，您可以像操作本地磁盘一样浏览目录、读取文件，也可以新建、编辑、复制、重命名和删除文件。典型场景如下：
说明
对象存储在访问延迟、数据提交可见性和多客户端一致性方面与本地磁盘存在差异。若您的应用依赖完整 NTFS 特性、数据库数据目录，或存在多客户端同时编辑同一文件的场景，请在使用前阅读使用限制 。
工作原理
tos-fsp 基于 WinFsp（Windows 文件系统代理）将 TOS Bucket 映射为本地盘符，Windows 应用可通过盘符直接访问 TOS 中的对象数据，无需集成 SDK。
请求转发流程
Windows 应用通过盘符发起文件请求（打开、读、写、列目录等）。
WinFsp 将请求转交给 tos-fsp 进程。
tos-fsp 通过 TOS SDK 访问后端存储桶，按需读取对象内容。
文件内容按需读取，挂载时不会下载整个存储桶的数据。

盘符是存储桶或指定前缀的本地访问入口，盘符本身不进入 TOS 对象 key。Windows 路径中的反斜杠 \对应 key 中的 / ，名称的大小写和 Unicode 字符原样保留。
Windows 路径与 TOS 对象的映射
目录通过对象前缀和必要的目录标记表示。例如在存储桶挂载中新建空目录 Z:\empty ，会创建目录标记对象 empty/ 。
挂载源 Windows 路径 TOS 对象 key
/tos/YOUR_BUCKET Z:\reports\a.txt reports/a.txt
/tos/YOUR_BUCKET:/windowsdata/ Z:\reports\a.txt windows-data/reports/a.txt
文件读写与提交机制
说明
写入调用返回不代表数据已经保存到 TOS，应用应正常保存、关闭文件。
读操作：按需使用本地缓存或直接请求 TOS。
写操作：先写入本地缓存，再通过刷新、关闭及正常卸载流程提交到 TOS。
强制结束进程：未提交的数据将会丢失，且无法自动恢复。

使用限制
tos-fsp 依赖网络连通性、TOS 服务可用性、有效访问凭证及可写的本地缓存目录。访问速度受网络状况、对象大小、请求并发数及本地磁盘性能影响。不支持离线访问、强制终止进程后未提交数据的恢复，以及跨客户端的事务保证。更多信息，请参见使用限制 。

问题 回答
可以同时挂载多个桶吗？
可以。
每次挂载都会启动独立进程，并使用不同的未占
用盘符；日志目录和缓存目录可以分别配置。
临时凭证可以自动续期吗？
不可以。
工具本身不会申请新凭证，需要由外部程序在凭
证到期前更新 JSON 凭证文件，工具按配置的间

mount.toml 配置示例。
可以为不同用户分别配置文件权限吗？
仅支持按文件维度配置所有者、所属组和其他用
户的读、写、执行权限。
在 Windows 上，工具通过本机 SID 与数字编号
的转换识别身份。不支持为任意命名用户配置独
立 ACL，也不支持权限继承和审计。更多信息，
请参见文件权限与身份规则 。
