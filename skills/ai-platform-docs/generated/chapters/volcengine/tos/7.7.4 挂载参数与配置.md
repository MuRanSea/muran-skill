挂载命令格式与挂载源写法
挂载命令格式为 tos-fsp.exe SOURCE MOUNTPOINT [-c CONFIG] [-o OPTIONS] [-f] 。
挂载源 SOURCE 的写法及 -c 、 -o 、 -f 与 Linux FUSE 一致；Windows 的挂载目标使用 MOUNTPOINT 盘符。
挂载源使用 /tos/<bucket>[:/prefix] 格式，不使用 tos:// URI。
共享配置
共享配置统一使用 -o 或 TOML，覆盖顺序为： -o > TOML > 默认值。
同一段 -o 内重复的键以最后一个为准， ro/rw 按先后顺序生效。
桶名和前缀由 SOURCE 提供，盘符由 MOUNTPOINT 提供； -f 控制前台运行。

Windows 选项校验与限制
程序启动前会校验 -o 选项，拒绝缺少值或不适用于 Windows 的选项。未知选项（包括拼写错误的选项）可能被忽略并记录告警，应检查启动日志，确认关键配置已生效。
FUSE 内核与 Linux 进程管理选项，例如 allow_other 、 auto_unmount 、 kernel_attr_ttl 、max_background 、 persist_dir 、 log_file 、 watchdog_log_level ，不能直接用于 Windows。Windows 目录枚举使用默认的 snapshot 模式，不支持 readdir_mode=stream ；配置为 stream 时挂载会启动失败。

多挂载缓存目录
默认情况下，多个挂载共用同一个系统临时基础目录，每个挂载的缓存分别存放在各自的独立子目录中。
缓存额度与空间占用规则如下： 
写缓存额度按挂载单独计算；当多个挂载位于同一磁盘时，各挂载的缓存空间会累加占用。建议为每个盘符单独配置 temp_dir ，以便于管理和清理。
挂载运行期间，请勿手动删除缓存目录。
缓存目录的清理规则如下： 
正常卸载时，工具会尝试清理本次挂载对应的写缓存子目录。
如果进程被强制结束、异常退出或清理失败，该子目录可能残留。
确认所有使用同一基础目录的挂载均已停止，且不再需要保留故障现场后，可手动清理残留的子目录。

缓冲预算
max_io_buffer_size = 0 时，Windows 会在启动时探测系统物理总内存，并取约 60% 作为缓冲预算。如果探测失败，程序会记录告警，并使用 1GiB 作为缓冲预算。
缓冲预算仅在启动时确定，不随当前空闲内存变化，也不会立即预分配全部预算。
此处的 0 表示自动选择，不表示关闭 NC 配额限制；如需固定预算，请显式填写正数。
句柄检查
open_handle_min_free_buffer_mb 通过 NC 缓冲预算减去已预约量的剩余额度进行判断，该值不对应Windows 当前空闲内存或进程 RSS。
当剩余额度不足时，程序会立即拒绝新的打开或创建请求，不进行排队，也不会关闭已打开的句柄。可在 TOML 中写 open_handle_min_free_buffer_mb = 4 ，或使用 -o open_handle_min_free_buffer_mb=4 覆盖。
设为 0 仅表示关闭该检查，句柄硬上限仍会单独生效。
日志优先级
日志级别可选 trace 、 debug 、 info 、 warn 、 error 、 off 。
挂载日志的优先级为： -o log_level=... > TOML > TOS_FUSE_LOG_LEVEL > info 。
NC 日志和审计日志的优先级分别为： -o nc_log_level=... / -o audit_log_level=... > TOML > NC_LOG_LEVEL / NC_AUDIT_LEVEL > info 。
环境变量均在启动时读取。

并发建议
日常挂载建议保留默认并发配置。
调大并发可能增加后端请求量、内存及本地磁盘压力，不保证访问更快。
如需调整日常挂载，请逐项修改，并结合实际业务负载进行观察与验证。
文件身份与默认权限配置
在 TOML 配置文件中，权限值使用八进制格式，例如 file_mode = 0o640 、 dir_mode = 0o750 ；通过挂载选项设置时，使用八进制数字字符串，例如 -o "file_mode=640,dir_mode=750" 。
UID 和 GID 使用十进制数字，不支持填写 SID 字符串。
查询时使用的默认值不会自动写回对象。新建对象保存实际创建者的身份，目录的组继承遵循共享核心规则。权限含义和身份边界，请参见使用限制 。
