6.3.5 权限管理
本文介绍 TOS Vectors 的权限管理方式、资源格式、权限动作及常用策略示例，帮助您为 IAM 用户、角色或其他账号配置向量桶、向量索引和向量数据的访问权限。
权限策略类型
主账号默认拥有全部权限，IAM 用户默认无权限。TOS Vectors 支持以下两种方式授予访问权限：IAM 策略：将策略绑定到 IAM 用户或角色，授予其访问 TOS Vectors 资源的权限。IAM 策略中通常无需指定 Principal，策略绑定的 IAM 身份即为授权主体。
向量桶策略：直接配置在向量桶上的资源策略，可通过 Principal 指定被授权的账号或 IAM 身份。设置向量桶策略需要 tosvectors:PutVectorBucketPolicy 权限。
建议遵循最小权限原则，仅授予完成业务所必需的 Action 和 Resource。
注意事项
区分服务前缀：TOS Vectors 的权限动作以 tosvectors: 为前缀，与普通 TOS 存储桶使用的 tos: 动作不同，配置时请勿混用。
遵循最小权限原则：优先按指定向量桶和必要 Action 授权，避免直接授予 tosvectors:* 和 Resource: "*" 。
谨慎授予策略管理权限：拥有 tosvectors:PutVectorBucketPolicy 的身份可以修改向量桶策略，可能进一步扩大资源访问范围。
确认授权主体：配置向量桶策略时，核对 Principal 对应的账号或 IAM 身份，避免误授权。匹配地域与资源：Resource 中的地域、账号 ID 和向量桶名称必须与目标资源一致。
显式拒绝优先：同一请求同时匹配 Allow 和 Deny 规则时，Deny 优先，系统将拒绝该请求。资源格式

策略示例
使用以下策略示例时，请将地域、账号 ID、向量桶名称和被授权主体替换为您的实际信息。示例一：允许查看指定向量桶及其中的索引和向量
以下 IAM 策略允许被绑定的 IAM 身份查看指定向量桶、索引和向量数据，但不允许创建、修改或删除资源。
示例二：允许读写指定向量桶中的向量数据
以下 IAM 策略允许被绑定的 IAM 身份读取、写入、查询和删除指定向量桶中的向量数据，但不允许删除向量桶或修改向量桶策略。

"tosvectors:GetVectors",
"tosvectors:QueryVectors",

"Resource": "trn:tosvectors:cn-beijing:2100000000:bucket/example-vector-bucket"
