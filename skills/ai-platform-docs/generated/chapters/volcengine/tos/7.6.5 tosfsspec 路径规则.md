7.6.5 tosfsspec 路径规则
本文主要介绍 tosfsspec 的 URL 与路径规则。tosfsspec 使用标准的 URI 格式来定位 TOS 上的资源。理解其路径约定是正确使用该库的基础。
协议
所有指向 TOS 资源的路径都必须以 tos:// 协议前缀开头。
路径结构
标准的 tosfsspec 路径结构遵循以下格式：
bucket_name : TOS 存储桶名称。
object_key : 对象在存储桶中的完整路径，可以包含多级目录，例如 data/raw/2023/log.txt 。示例：
指向一个具体文件： tos://my-bucket/documents/report.pdf 。
指向一个目录： tos://my-bucket/images/ （末尾 / 可选，但推荐用于表示目录）。
指向 Bucket 根目录： tos://my-bucket 或 tos://my-bucket/ 。
特殊路径
根路径 ( / 或 '' )
当你提供的路径是根路径（ '/' ）或空字符串（ '' ）时，tosfsspec 的少数操作会表现出特殊的行为，通常用于列举所有存储桶。
注意
除了 fs.ls() 等少数操作外，绝大多数文件操作（如 open() , touch() , rm() ）都不支持直接对根路径进行；必须指定一个明确的 Bucket。
tos://<bucket_name>/<object_key>
Plain
# 以下两种方式都用于列出所有 buckets
all_buckets_1 = fs.ls('/')
all_buckets_2 = fs.ls('')
print([b['name'] for b in all_buckets_1])

仅指定 Bucket
如果只提供 Bucket 名称（无论是否带协议），多数情况下等同于指向该 Bucket 的根目录。路径解析
tosfsspec 内部会自动将提供的 URL 解析为 bucket 和 key 两部分。
tos://my-data/input.csv -> bucket='my-data' , key='input.csv'
tos://archive-logs/2023/q1/ -> bucket='archive-logs' , key='2023/q1/'
tos://assets -> bucket='assets' , key=''
理解这个解析规则有助于您排查因路径格式不正确导致的问题。
#这两种写法在 ls() 中是等价的，都会列出 my-bucket 下的顶级文件和目录
fs.ls('tos://my-bucket')
fs.ls('tos://my-bucket/')
