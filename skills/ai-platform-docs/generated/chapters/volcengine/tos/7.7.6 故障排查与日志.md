7.7.6 故障排查与日志
本文主要介绍 tos-fsp 在 Windows 上出现异常时的标准排查路径，帮助您按统一顺序定位问题、收集诊断信息并完成反馈。
排查原则
按下文六个步骤依次检查，每完成一步先判断问题是否已定位并解决，解决后即可停止；仅在现有信息不足以判断时，才提高日志级别并重新复现问题。
开始排查前，请先保留完整的报错信息、操作时间和执行的命令。如果程序本身无法启动，日志文件可能尚未生成，此时应保留原始终端输出或系统错误提示。

步骤二：找到日志
日志目录
日志目录的优先级为： -o log_dir=... 高于 TOML 中的 log_dir 。均未指定时，日志按挂载盘符分别写入 %LOCALAPPDATA%\TosFsp\logs\Z ，末尾的 Z 是按挂载盘符命名的日志子目录，用于区分不同挂载，例如挂载 E: 时目录为 E 。当 LOCALAPPDATA 不存在时，写入系统临时目录下的 TosFsp\logs\Z 。日志文件说明
各组件日志的文件名包含日期和序号，按并发、资源、超时及日志配置中配置的单文件大小、按天轮转及保留份数执行轮转； startup.log 单独追加写入，不参与组件日志轮转。所有文件日志共用同一套日志组件，正常卸载时会排空日志队列。
前台模式还会向终端输出日志。未配置挂载日志级别时，可使用 RUST_LOG 对前台终端输出进行筛选，但该方式不能替代文件日志级别的配置。
步骤三：按失败阶段定位
定位日志时可使用两类标识： winfsp_request 中的回调名称和 req_id 用于关联同一次 Windows 请求，NC 日志中的服务端 request id 用于查询对应后端请求。
正常探测不存在的对象也可能返回 404，不能将所有 404 都判定为业务故障。日志时间戳带 Z 后缀时表示 UTC 时间，反馈问题时请同时注明本地时间和所在时区。

步骤六：收集日志并反馈
打包同一次运行的日志
记录问题发生的本地时间、时区和原始错误信息。能够正常卸载时，先保存文件并按正常卸载完成卸载，使日志写入完整；卸载失败时直接收集已有日志，不要强制结束进程。
将整个实际日志文件夹复制到其他本地目录，例如桌面的 TosFsp-logs-Z 。须保留文件夹内的全部组件日志和已有的 startup.log ，不要只复制最后一个文件，也不要仅提供终端截图。
右键单击复制后的文件夹，选择压缩为 ZIP 文件；旧版 Windows 可选择发送到 > 压缩(zipped)文件夹。压缩完成后，确认压缩包内包含日志文件。
现象 处理方式
正常卸载超时 检查网络及提交日志，必要时延长等待时间后重
试；不要强制结束仍持有未提交数据的进程。
没有日志，或调整日志级别后未生效
确认实际使用的 log_dir 和文件级别，并重新
启动挂载；加载器错误可能发生在日志初始化之
前。

log_level = "debug"
nc_log_level = "debug"
audit_log_level = "info"

反馈时需提供的信息
完整命令、原始错误码和最小复现步骤，并注明使用的是 CMD。
失败路径、发生时间及时区，以及创建、写入、关闭、删除、列举等操作的先后顺序。
同一次运行产生的日志压缩包，以及出问题时的终端或应用错误输出。
EXE 的发布版本或文件哈希、Windows 版本、WinFsp 版本，以及是否使用管理员终端。版本信息可在系统的关于页面和 WinFsp DLL 的**属性 ** > 详细信息中查看。
脱敏配置：发送前须去除 AK、SK、token，并检查日志及业务路径中是否包含其他敏感信息。
