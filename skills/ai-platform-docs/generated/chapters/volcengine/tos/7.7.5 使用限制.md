本文主要介绍 tos-fsp 的相关使用限制。
删除、重命名与已打开句柄
删除和重命名受打开句柄、共享访问权限、只读属性及目标冲突约束。操作结果以系统返回和挂载日志为准，常见情况及处理方式如下：
应用显式替换已有文件时，仍受目标属性和共享访问权限约束，不提供多对象或多客户端事务。保存、删除异常应以实际操作结果和挂载日志为准；卸载汇总不能代替每次操作的错误处理。
Windows 删除与重命名规则，请参见 Microsoft DeleteFileW 说明 和重命名说明 。
目录、缓存及持久化
文件在挂载盘内可见，不等于数据已保存到 TOS。日常操作还需区分当前挂载与其他挂载或客户端之间的可见性差异。
单挂载与多客户端可见性
其他客户端修改桶后，本挂载也可能因缓存暂时保留旧结果。刷新应用视图不一定立即清除所有缓存，不应依赖多个挂载同时编辑同一文件。

保存、关闭及失败处理
日常使用时，应先在应用中保存并关闭文件，并在正常卸载时检查返回结果和日志。
延迟创建时，被其他客户端抢先创建同名文件等冲突可能到首次提交时才报错。
需要在程序中明确确认提交结果时，应由程序在关闭句柄前对该文件调用 FlushFileBuffers 并检查返回值。
应用应检查刷新、关闭和卸载返回结果，并结合日志确认提交状态，具体错误报告行为以当前版本为准
Close 阶段的提交失败会记录日志，并在正常卸载时与本次资源收尾失败一并汇总报告。即使盘符消失，卸载仍可能报错，应检查卸载结果和日志。
卷级 Flush 只处理当前仍打开的文件，不保证补报已关闭句柄的历史失败。
挂载根目录
整桶挂载的根目录没有对应对象，修改其属性和时间只在当前挂载内生效。
挂载 foo/ 前缀时，根目录属性和时间保存在桶内的 foo/ 目录对象上，重新挂载后可以恢复；如果目录对象尚不存在，首次修改属性时创建，读取不会创建对象。
发生网络故障、凭证过期、缓存磁盘耗尽或进程异常退出时，数据可能未成功提交。保存或卸载报错时应保留日志并核对对应对象；需要检查持久化结果时，可正常卸载后重新挂载读取，或在 TOS 控制台核对。

文件权限与身份规则
挂载盘支持查询和修改基本文件权限，但不提供完整 NTFS ACL。与本地 NTFS 磁盘的主要差异如下：身份与跨平台规则
文件身份依赖本机或域账号环境，换一台机器或切换域后不保证能识别原来的所有者和组。无法识别已有身份时会报错，不会自动归给挂载用户。
只读挂载不允许修改权限。
Windows 与 Linux 共用对象上的 mode / uid / gid 元数据，一侧保存的权限或所有权修改也会影响另一侧；相同数字编号不代表两端的同一账号。
默认 file_mode = 0644 不含执行权限，直接运行挂载盘上的 .exe 可能被拒绝。可通过文件身份与默认权限配置的 file_mode 调整缺省权限；已保存权限元数据的文件需单独修改自身权限。

对象名称与路径限制
通过 SDK 或其他客户端创建的部分对象名不适合通过普通 Windows 应用访问。跨平台共享的桶建议在创建对象时就避开下表所列的命名方式。
同一条名称在不同应用中的表现和报错文案可能不一致，下表以挂载路径本身的处理结果为准。除上表外，还需注意以下两点：
仅大小写有差异的多个名称可能在部分应用中被视为同一个，跨平台共享桶时应尽量避免。单个名称最多包含 255 个 UTF-16 单元，完整路径的长度同时受后端 key 长度限制和所用应用自身限制的约束。

名称中含反斜杠（如 a\b.txt ）
Windows 会把反斜杠解析为目录分隔符，原对
象名被拆分为多级路径，无法按原名访问。
名称含 * 、 ? 、 " 、 < 、 > 、 \| 不符合普通 Win32 文件名规则。
名称以空格或 . 结尾，如 x.
部分 Windows 应用会自动裁掉结尾字符，发出
的请求与原对象名不一致，从而无法定位对象。
CON、NUL、aux.txt 等 这类名称与 Windows 保留设备名重合，可能被
系统按设备而非普通文件处理。
a//b.txt（包含空路径段） 连续斜杠构成空路径段，挂载路径不允许空名
