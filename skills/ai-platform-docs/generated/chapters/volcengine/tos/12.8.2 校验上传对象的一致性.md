12.8.2 校验上传对象的一致性
您可以利用 Content-MD5、Content-SHA256 或 CRC64 实现上传对象的一致性校验。本文介绍不同方案的校验流程图、示例代码以及各方案的对比信息。
通过 Content-MD5 校验
调用 TOS API 接口上传对象或上传分片时，将客户端计算出的待上传数据的 Content-MD5 值，通过请求头域或表单域传递给 TOS，从而保证上传数据的一致性。

通过 Content-SHA256 校验
和利用 Content-MD5 校验的方式相同，调用 TOS API 接口上传对象或上传分片时，将客户端计算出的待上传数据的 Content-SHA256 值，通过请求头域或表单域传递给 TOS，从而保证上传数据的一致性。流程图

hash.update(data.encode())
content_md5 = base64.b64encode(hash.digest()).decode()
client = tos.TosClientV2(access_key, secret_key, endpoint, region)
try:
 resp = client.put_object(bucket, key, content=data, content_md5=content_md5)

通过 CRC64 校验
调用 TOS API 接口上传对象或上传分片完成后，将客户端计算出的已上传数据的 CRC64，与 TOS 返回的CRC64 做比较，从而保证单次 API 上传数据的一致性。
在分片上传场景中，除了验证单次上传的 CRC64 外，在合并分片后，通过组合各个分片的 CRC64 再与服务端返回的整个对象的 CRC64 做比对，进而保证最终 TOS 侧生成对象的数据一致性。

推荐说明

如果希望数据不一致时不在 TOS 侧生成对象，且希望使用更安全的哈希
