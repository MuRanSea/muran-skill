7.4.8 FSX 故障排查与处理
本文介绍在使用 FSX 客户端过程中遇到故障时如何进行排查解决。
权限问题
挂载存储桶时报错 “error: Auth Failed”
问题原因：
挂载存储桶使用的 Access Key ID 和 Secret Access Key 填写有误或权限不足。
解决方案：
检查挂载时填写的 Access Key ID 和 Secret Access Key 是否正确。
确保挂载时使用的 Access Key ID 和 Secret Access Key 所属账号具有挂载存储桶的最小权限，详细介绍，请参见挂载存储桶所需要的权限。
存储桶挂载成功后，读取文件时报错 “Permission denied”
问题原因：
读取的是未恢复的归档存储、冷归档和深度冷归档类型的文件。
挂载时使用的 Access Key ID 和 Secret Access Key 权限不足。
解决方案：
检查读取的文件类型，如果是归档存储、冷归档和深度冷归档类型的文件，需要恢复后才可以读取。确保挂载时使用的 Access Key ID 和 Secret Access Key 所属账号具有读取文件（GetObject ）的权限，详细介绍，请参见挂载存储桶所需要的权限。
挂载问题
挂载时报错 “Mount target directory is not exist”
问题原因：
挂载存储桶前，未创建指定的挂载目录。
解决方案：
创建指定的挂载目录后，再执行挂载操作。具体操作，请参见 FSX 配置与挂载。

问题原因：
重启系统前，没有卸载挂载点。由于没有卸载挂载点， reboot 命令会先关闭所有用户进程（包括 FSX 进程），再去执行 umount 命令。FSX 工具支持崩溃恢复， umount 命令不会立即返回失败，会阻塞（等待FSX 进程恢复），从而阻塞 reboot 命令。
解决方案：
建议您强制重启系统，或者等待一段时间，系统会自动恢复重启。

读写问题
在 FNS 存储桶追加写场景中，为什么会出现对即将追加的数据进行拷贝的情况？
问题原因：
FSX 工具追加写操作在不同类型的存储桶，实现原理不同，具体实现原理如下：
追加写 FNS 存储桶中的对象时，云端的历史数据会使用 UploadPartCopy 接口对 TOS 中的数据进行复制，追加的新数据则使用 UploadPart 或 PutObject 接口进行上传。该场景下，一次 open 操作仅支持一次 flush 操作。
追加写 HNS 存储桶中的对象时，TOS 会使用 AppendObject 接口进行数据的追加写操作。该场景下，支持对追加写的对象执行多次 flush 操作。
解决方案：
如果您不希望出现请求次数放大的情况，推荐使用 HNS 存储桶。
挂载存储桶后，访问目录失败
问题原因：
通过 FSX 挂载存储桶后，系统会将 / 结尾的对象识别为目录。如果您创建了同名的目录和文件（例如test/ 和 test），由于名字相同，系统无法区分，导致访问目录失败。
解决方案：
如果系统中存在同名的目录和文件，建议您重命名文件和目录，确保文件和目录的名称不重复。后续请勿创建同名的目录和文件，以防命名冲突。

向挂载目录写入文件失败
问题原因：
写入文件过大，超出限制或不符合推荐写入方式。
并发写入同一个文件：第一个写请求成功，其余写请求失败。
使用 O_TRUNC 标志打开正在读写的文件，引发冲突。
以偏移量 0 覆盖写已存在文件，引发 FSX 对写逻辑的拦截。
解决方案：
针对大文件写入，请参考上传大文件 进行排查和优化写入方式。
避免对同一文件进行多路并发写入，必要时对应用侧进行串行化或加锁控制。
不要在文件被读写时使用 O_TRUNC 打开文件，避免强制截断正在访问的文件。
避免以偏移量 0 对已存在文件直接覆盖写入，对写逻辑进行调整以规避被拦截场景。
在挂载目录删除文件失败
问题原因：
挂载时未携带 tos_allow_delete 参数，导致删除权限受限。
被删除文件正在被其他进程并发读写。
解决方案：
确认挂载命令中已正确配置 tos_allow_delete 参数，并在必要时重新挂载。
检查是否有其他进程在访问目标文件，停止相关读写操作后重新尝试删除。
追加写请求失败
问题原因：
挂载时未携带 tos_incremental_upload 参数，追加写能力未开启。
追加期间有其他并发修改导致远端数据发生变化，从而追加失败。
解决方案：
在挂载参数中添加 tos_incremental_upload ，重新挂载后再进行追加写操作。
避免在追加写时对同一文件进行其他并发修改。
磁盘内存问题
在 FSX 客户端读写过程中，为什么会写满磁盘空间？
问题原因：
FSX 客户端写入数据时，默认会在 /tmp/ 下写入临时文件，如果写入文件超过磁盘空间大小，可能会写满磁盘空间。
在读缓存场景下，配置的读缓存空间大小超过磁盘空间，可能会写满磁盘空间。
解决方案：
写数据的临时文件目录空间至少需要保证 10240*分段数据的大小，在默认分段数据大小为 8MB 的场景下，临时文件目录空间需要 80GiB 的空间，因此需要确保磁盘空间大于 80GiB。
在读缓存场景下，请确保配置的 max_read_cache_size （读缓存占用最大空间）小于磁盘空间。在开启读缓存和写缓存时，建议至少为 FSX 客户端预留 120GiB 的磁盘空间。为避免跟系统其他应用争抢磁盘空间，推荐为这部分磁盘空间划分独立分区，详细介绍，请参见 FSX 挂载参数说明。为什么执行 df 命令后显示磁盘空间大小为 8.0EB？
问题原因：
df 命令展示的数值仅为展示值，不代表存储桶的实际物理空间。其中， Size （磁盘空间总大小）和Avail （磁盘空间剩余可用大小）固定为 8EB， Used （已使用磁盘空间大小）固定为 0 。解决方案：
避免使用 df 命令的返回结果来判断存储桶的实际磁盘空间使用情况。
