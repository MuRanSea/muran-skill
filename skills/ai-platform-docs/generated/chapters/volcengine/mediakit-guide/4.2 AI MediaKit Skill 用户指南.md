4.2 AI MediaKit Skill 用户指南
AI MediaKit Skill 是一套基于 mediakit-cli 构建的 Agent 工具包。安装并配置后，您可以在支持的 AgentRuntime（如 Trae）中通过自然语言描述需求，Agent 便会自动调用对应的 mediakit-cli 命令来完成音视频处理任务，无需手动编写和拼接命令行参数。
本文档将介绍 Skill 的功能列表、安装与配置方法，并提供典型应用场景的示例。

常见问题
Q1: Agent 未使用 mediakit-cli，而是尝试调用原生 ffmpeg 命令，应如何处
理？
这通常由两个原因导致：
Skill 未正确安装：请检查您的 Agent Runtime 对应的 skills 目录下是否已包含 byted-mediakit-* 的文件或软链接。如果不存在，请返回“安装 Skill”章节，重新执行安装步骤。
Skill 未被正确加载或描述未命中： 
首先，直接向 Agent 提问：“你当前可用的 skill 列表是什么？” 如果列表中没有 mediakit 相关Skill，可能是 SKILL.md 文件格式有误，或 Runtime 需要重启才能加载新 Skill（尤其是 Trae）。如果 Agent 能列出 Skill 但未使用，请尝试使用更明确的指令，例如：“用 mediakit-cli 帮我裁剪视频”。
Q2: 调用云端功能时，返回“凭据未配置”的错误，是什么原因？
这表示 MEDIAKIT_API_KEY 环境变量未被程序正确读取。请执行 mediakit-cli config show | grep api_key 命令进行验证。预期输出应包含您的 API Key 信息，而不是 <not configured> 。如果未配置，请重新运行 mediakit-cli init 或通过 export MEDIAKIT_API_KEY=<key> 命令手动设置环境变量。
Q3: 在本地模式下执行任务时，出现缺少编解码器（如 openh264）或字体库
（如 libfribidi）的错误，该如何解决？
本地执行部分视频转码或处理任务（如视频翻转、调速、加水印、加字幕）依赖 FFmpeg 的特定构建版本。最简单的解决方案是优先使用云端模式，在 init 时选择 --mode cloud-first （此为默认设置），这样就不再依赖本地环境。
Q4: Skill 的默认执行模式是云端还是本地？
默认模式是 cloud-first （优先使用云端）。但行为会根据配置发生变化：
如果 MEDIAKIT_API_KEY 未配置，CLI 会自动降级到 local （本地）模式，并在标准错误流中打印一条警告信息。
为确保行为可预测，建议在调用时显式指定 --cloud 或 --local 标志，避免因环境配置不确定而导致的模式自动切换。
Q5: Agent 是如何知道每个功能支持哪些参数的？
每个 Skill 的 SKILL.md 文件中包含了所有工具的基本描述。当需要获取详细参数信息时，Agent 会调用命令并附加 --schema 标志，例如 mediakit-cli editing add-image-to-video --schema 。该命令会返回一个包含 input_schema 和 output_schema 的 JSON Schema，Agent 可据此了解所有可用参数、数据类型、是否必填、枚举值及默认值等详细信息。

Q7: Trae 中安装 Skill 后无法识别，如何排查？
Trae 加载 Skill 的机制与 Claude Code 可能存在差异。如果您遇到此问题，请按以下步骤排查：重启 Trae：完全退出并重新启动 Trae 应用程序。多数情况下，新安装的 Skill 需要重启后才能被加载。检查路径解析：执行 ls -L ~/.trae-cn/skills/byted-mediakit-editing/SKILL.md 命令（ -L 选项会解析软链接的最终路径），确保能够正常读取文件内容。
检查内置 Skill 冲突：检查 Trae 的 builtin_skills 目录，确认是否存在与您安装的 Skill 同名的工具包，避免因命名冲突导致自定义 Skill 被覆盖。
检查 Trae 设置：确认 Trae 的设置中是否包含“启用自定义 Skill”等相关选项，并确保其已开启。
