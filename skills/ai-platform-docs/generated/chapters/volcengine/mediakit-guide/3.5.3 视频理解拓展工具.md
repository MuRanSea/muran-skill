火山方舟视觉大模型可理解视频中的视觉信息，完成如描述其中的物体、分析动作逻辑等视觉相关任务。AI MediaKit 视频理解能力是对火山方舟平台视觉理解能力的工程级增强，依托视频云深厚的媒体处理基础设施，将 URL 传入方式的视频上限从 50 MB 放宽至 5 GB，满足工业级长视频、高码率素材的分析需求。
本篇开发指南将引导您：

控制视频理解的精细度和 Token 成本
您可以通过组合使用 fps 、 max_frames 和 max_pixels 三个参数，精细地平衡视频理解的分析粒度与Token 成本。
控制时间粒度 ( fps ) ：通过 fps 字段控制抽帧频率，默认为 1 （每秒 1 帧）。 
若需分析快速变化的动作（如体育赛事中的进球瞬间），可适当调高 fps （最高为 5），以捕捉关键画面。
若视频内容变化平缓（如风景延时），可调低 fps （最低为 0.01），以加快处理并节省成本。控制空间粒度 ( max_pixels ) ：通过 max_pixels 字段限制单帧画面的最大分辨率（ 宽 × 高 ）。对于高分辨率视频（如 4K），如果不关心画面中的微小细节，可以设置一个较低的 max_pixels 值。系统会在分析前缩小图片尺寸，从而显著降低单帧画面的 Token 消耗。
控制总帧数上限 ( max_frames ) ：通过 max_frames 字段为任务设定一个绝对的抽帧数量上限。这提供了一个独立于视频时长和 fps 的成本“熔断”机制，确保总帧数不会超过您的预期。

时序信息
基于 FPS 的抽帧获取视频帧，再通过时间戳+图像拼接标记时序信息，模型基于该请求中的时序标记和图像内容，实现对视频的完整理解（包括内容变化、动作逻辑、时序关联等）。详细信息见视频理解工作原理。
视频格式说明
支持 MP4、FLV、ASF、RM、RMVB、MPEG、MOV、AVI、MPEGTS、M4S、WMV、3GP、TS、MPG、
WEBM、MKV、MPE、VOB、DAT、MP4V、M4V、F4V、MXF、QT 等主流视频格式。

抽帧策略
AI MediaKit 视频理解服务内置了成本控制机制，默认将单次视频处理的总 Token 消耗限制在 200k 以内，确保任务稳定运行，避免超长视频或高分辨率素材导致上下文窗口溢出或费用失控。
抽帧决策遵循以下逻辑：
计算单帧 Token 成本：AI MediaKit 首先会检查您是否设置了 max_pixels 参数。如果视频原始分辨率（ 宽 × 高 ）超过 max_pixels 的限制，系统会先将图片等比缩小，然后再根据缩小后的分辨率，参考图片 token 用量估算规则 估算单帧画面的 Token 消耗。 
默认 max_pixels ：若不设置，默认为 677,376。
最大 max_pixels ：最大值为 9,031,680，超出部分按最大值计算。
计算预算内最大帧数：根据第一步算出的“单帧 Token 成本”，系统用总预算（200k Token）计算出在此成本下，最多能处理多少帧图像，这个数量即为 MaxFrames_budget 。
抽帧方案判定：系统会综合评判 fps 、 max_frames 和 MaxFrames_budget ，选择最严格的限制来执行抽帧： 
首先，根据视频时长和用户设置的 fps 计算出一个理论抽帧数（ 理论帧数 = 时长 × fps ）。然后，如果用户还设置了 max_frames ，则将理论抽帧数与 max_frames 取较小值，得到“用户期望帧数”。 用户期望帧数 = min(时长 × fps, max_frames)
最后，将“用户期望帧数”与系统预算的 MaxFrames_budget 进行比较： 
预算充足：如果 用户期望帧数 ≤ MaxFrames_budget ，系统将完全按照用户的设定（ fps 和 max_frames ）执行抽帧。
预算不足：如果 用户期望帧数 > MaxFrames_budget （通常发生在长视频、高 fps 或高分辨率场景），系统将忽略用户设定的 fps 和 max_frames ，强制采用 MaxFrames_budget 作为最终抽帧数，并在整个视频时长内均匀采样，以确保在不超预算的前提下，无论视频多长，模型都能获取覆盖全片的视觉信息，而不会因为超出窗口导致任务失败。
