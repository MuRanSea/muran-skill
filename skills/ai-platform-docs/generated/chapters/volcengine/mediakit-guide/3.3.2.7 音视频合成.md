3.3.2.7 音视频合成
AI MediaKit 的音视频合成工具可以帮助您轻松地为现有视频添加新的音轨。通过音视频合成工具，您可以实现音频混合（将新音频与视频的原有音轨混合）或音频替换（移除视频的原有音轨，替换为新的音频内容）。无论是为视频配上背景音乐（BGM）、替换为新的旁白，还是将两者混合，都可以通过简单的 API 调用实现。
本篇开发指南将引导您：
理解音视频合成的核心能力与应用场景。
快速体验为一段视频添加背景音乐。
学习如何通过参数控制音频的混合方式与音量。
快速体验：为视频添加背景音乐
本场景演示如何为一段无声的视频（或希望保留原声的视频）添加一首背景音乐。
准备工作
获取访问凭证：在开始之前，访问 AI MediaKit 控制台 API Key 管理页面 ，创建并获取 AI MediaKitAPI Key（用于媒体处理功能鉴权）。
准备媒体文件：准备一个待处理的视频文件和一个待添加的音频文件，将它们上传至公网可访问的服务器或视频点播服务 中，以获取可供 API 调用的 URL。
操作流程
音视频合成是一个异步任务：
成功调用 POST /api/v1/tools/mux-audio-video 后，API 将返回一个任务 ID。
您可以轮询 GET /api/v1/tasks/{task_id} ，直到任务状态 status 变为 completed ；或者使用事件回调自动接收任务状态变化。
任务完成后，解析 result 字段，即可在 video_url 字段处获取最终合成视频的下载地址。第 1 步：提交任务
您需要调用提交音视频合成任务 API 。您可以直接复制以下 cURL 命令，提交一个音视频合成任务。说明
curl -X POST 'https://mediakit.cn-beijing.volces.com/api/v1/tools/mux-audio-video' \
--header 'Content-Type: application/json' \

进阶使用
替换或保留视频原声
您可以决定是保留视频的原始音轨（与新音频混合），还是将其完全替换。
场景：为有对话的视频添加较轻的背景音乐时，应选择保留原声；为视频更换配音或 BGM 时，应选择替换原声。
参数： is_audio_reserve
true ：保留原音轨，新音频将与原音频混合。此为默认行为。
false ：不保留原音轨，即用新音频替换。
示例：将视频原声替换为新的旁白
对齐音视频时长
当输入的视频和音频时长不一致时，您可以通过将 is_video_audio_sync 参数设为 true 启用时长对齐功能，并进一步通过 sync_mode （对齐基准）和 sync_method （对齐方式）来确定最终效果，确保输出视频的整洁性。涉及参数说明如下：
is_video_audio_sync ：设为 true 以启用时长对齐功能。默认为 false ，即不启用时长对齐功能。输出文件的总时长由输入流中较长者决定，具体表现如下： 
若音频长于视频：视频流终止后，输出文件在剩余时间内将维持末帧画面，直至音频结束。若视频长于音频：音频流终止后，输出文件在剩余时间内将保持静音，直至视频结束。
sync_mode ：指定以哪个文件为时长基准。 
"video" ：（默认）以视频时长为准。
"audio" ：以音频时长为准。
sync_method ：指定具体的对齐处理方法。 
"trim" ：（默认）裁剪较长的文件。
"speed" ：通过变速处理，使两个文件时长一致。

最佳实践
如何选择时长对齐方式？
**优先使用 ** trim （裁剪） ：在大多数场景下，裁剪是最佳选择。它能保证音视频的原始播放速率和音调不变，只舍弃多余的部分，听感和观感最自然。
**谨慎使用 ** speed （变速） ：变速功能适用于音视频时长差异较小（建议在 10% 以内）的场景。如果时长差异过大，可能会导致以下问题： 
视频变速：画面出现明显的卡顿感（慢放）或鬼畜感（快放）。
音频变速：声音音调发生变化（变尖或变沉），或出现不易听清的情况。
