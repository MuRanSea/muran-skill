4.1 AI MediaKit CLI 用户指南
AI MediaKit CLI ( mediakit-cli ) 是 AI MediaKit 的官方命令行工具，将视频剪辑、音频处理、画质增强、字幕擦除等核心能力封装为一组统一、标准、极简的终端命令。不仅如此， mediakit-cli 还支持导出符合JSON Schema 规范的能力声明，能够与各类 AI 智能体（Agent）无缝集成，在显著降低 Token 消耗的同时，通过自然语言任务描述自动编排并完成复杂的音视频处理。本文为您详细介绍 mediakit-cli 的安装、配置与核心使用方法。
快速开始：从云端增强到本地剪辑
本节以具体的云端画质超分和本地视频剪辑功能为例，引导您在几分钟内完成从安装、配置 mediakit-cli到成功产出第一个处理视频的全过程。

核心使用方法
统一命令结构
mediakit-cli 的命令都遵循以下统一的语法结构：
<domain> ：能力域（如 editing 代表剪辑、 video 代表视频处理）。
<tool> ：具体原子工具名（如 trim-video 代表视频裁剪）。

输出路径优先级
输出文件的存放位置由以下规则决定，优先级从高到低：
命令行的 --output-path <path> flag。
MEDIAKIT_OUTPUT_PATH 环境变量。
通过 config set output-path <path> 设置的全局配置。
默认路径 ~/.mediakit/temp 。
执行模式与降级
优先级：单次命令的 --local / --cloud flag > 全局配置的 mode > 默认值 ( cloud-first )。静默降级：当模式为 cloud-first 但 API Key 未配置时，CLI 会静默降级到 local-first 模式，并在标准错误流中打印一条警告。
Agent 调用建议：为了避免意外的静默降级，建议在 Agent 或自动化脚本中显式地使用 --cloudflag，这样在未配置 Key 时会立即报错，而不是执行非预期的本地任务。
注意
退出码已知限制：当前版本中，部分客户端错误（如传入互斥 flag）的退出码（ exit code ）可能仍然是 0 。请在脚本中同时检查响应的 JSON 体是否包含 error 字段，而不是单独依赖退出码来判断成功或失败。

### Q6：为什么我的命令出错了，但 Shell 脚本里的 `$?` 还是 0？
这是当前开发版本的已知限制，部分客户端参数校验报错未能正确映射到退出码。在编写自动化脚本时，**请勿仅依赖退出码判断状态**。建议检查输出的 JSON 内容中是否包含 `"error"` 字段：```Bash
result=$(mediakit-cli ... 2>/dev/null)
if echo "$result" | grep -q '"error"'; then
 echo "执行失败: $result"
 exit 1
fi
Q7：Agent 调用时，默认走云端还是本地？
默认是 cloud-first 。但是，如果 MEDIAKIT_API_KEY 未配置，CLI 会静默降级到本地模式。为避免非预期的行为，建议在 Agent 或自动化脚本中显式地使用 --cloud flag，确保在未配置 Key 时能立即报错而不是悄悄降级。
