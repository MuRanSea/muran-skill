10.3.7.5 会话事件结构参考
托管智能体会话支持 6 种 user.* 客户端事件，以及必须与 user.message 一同发送的 system.message 。服务端当前可推送 26 种事件，流式订阅还可以返回 2 种瞬时预览帧。本参考文档列出这些事件和预览帧的结构、字段含义和触发时机。
说明
客户端事件通过 发送会话事件 接口提交；服务端事件可通过 流式获取会话事件 实时消
费，或通过 获取会话事件列表 查询历史。预览帧只在流式接口中出现。
客户端发送事件时，公共字段中的 id 、 processed_at 等由服务端自动生成，客户端仅需要填写事件类型（ type ）和对应业务字段即可。
system.message 必须与一条 user.message 放在同一个 events 数组中，并紧跟在该 
user.message 后发送；单独发送 system.message 会被服务端拒绝。
多态对象通过 type 字段区分具体结构。客户端应先读取 type ，再按对应变体解析其余字段。
事件 ID、结果评估 ID 和线程 ID 分别以 sevt- 、 outc- 和 sthr- 开头。
user.message 的 content[] 支持 video 内容块。 source 支持 url （不超过 50 MB）、base64 （ video/mp4 、 video/x-msvideo 或 video/quicktime ）和 file （Files API 上传的视频文件 ID）；可以通过 fps 控制抽帧频率，取值范围为 0.2～5，默认值为 1。
event_start 和 event_delta 仅在流式接口通过 event_deltas 参数显式订阅后返回，不写入事件历史。
订阅主线程时也可能收到子线程的创建和状态变化通知；子线程内部消息仍需订阅或查询对应线程。流式响应可能为线程内事件补充 session_thread_id ，事件历史接口可能省略该字段。下方事件结构仅列出事件自身定义的字段。
