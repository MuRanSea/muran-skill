11.4.12 Webhook 事件结构参考
当 Agent 运行状态、资源变更或凭证刷新等订阅事件发生时，Managed Agents Webhook 会向接入点推送统一事件信封。本文列出当前可订阅的业务事件，并说明用于验证接收链路的 webhook.test 测试事件。Webhook 事件是独立通知，不等同于 Session Events 查询或 SSE 返回的原始事件。
每个事件使用以下统一信封。外层 type 固定为 event ， id 是以 whe- 开头的 Webhook 事件 ID；data.type 是业务事件类型， data.id 是触发事件的资源 ID。
事件正文生成后保持不变；同一事件向多个接入点投递或重试时，外层 id 、 created_at 和正文均不变。
说明
Webhook 不保证严格顺序或恰好一次投递。接收端应按外层 id 去重，并通过资源查询接口读取当前状态。
session.status_running 映射为 session.status_run_started ； session.status_idle 映射为 session.status_idled 。原 Session 事件名称不变。
session.status_idled 只表示 Session 已进入空闲状态，不表示当前轮次正常结束。使用 data.id查询该 Session 的历史事件，并根据业务侧记录的本轮边界定位对应的 session.status_idle ；无法确认对应关系时，不要仅凭最近一条 end_turn 自动推进业务。Webhook 外层 whe- ID 不能作为 Session Event ID 使用。
线程事件的 data.id 是所属 Session ID， data.session_thread_id 是发生状态变化的线程 ID。凭证事件的 data.id 是凭证 ID， data.vault_id 是所属 Vault ID；删除事件保留删除前的所属关系。
查询事件信封：使用 查询 Webhook 事件列表 或 查询 Webhook 事件详情 读取最近 7 天内与接入点关联的冻结事件信封。
处理回调：回调验签、重试和停用规则请参见 使用 Webhook 接收事件通知 。
