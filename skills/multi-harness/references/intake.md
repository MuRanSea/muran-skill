# 对话式规划

用于新目标、新协作组或需要重新规划的工作。借鉴访谈式收敛：用户决定偏好，Codex 查明环境事实、提出推荐并承担技术配置。已有任务的进度、点名、暂停与继续直接按对应契约处理。

## 每轮一个选择

先从当前消息、已确定的对话内容和明确选中的团队中提取答案。一次只问一个会改变交付结果的选择，提供两三个简短选项，把推荐及理由放在前面；等用户回答后再决定下一问。使用当前环境允许的提问工具，工具不可用时用普通文本提问。

优先解决当前尚未确定、且其他选择依赖它的问题：

| 需要确定什么 | Codex 应做什么 |
|---|---|
| 目标与交付 | 把宽泛目标变成可验收的结果；例如研究报告、可运行 demo、代码修复。对象有歧义时先确认对象。 |
| 深度与范围 | 结合用途推荐篇幅、研究重点或改动边界；只问会改变结果的取舍。 |
| 分工与模型 | 根据任务提出精简团队，给出职责、CLI、完整模型 ID 和必要的 effort；用户可接受整套推荐或只替换一项。 |
| 路径与验收 | 优先使用已指定目录或当前项目，提议合理输出位置与验收方式；需用户决定的边界集中在这一轮。 |

这不是每次必答的问卷。已明确的项直接沿用；信息齐全时直接进入方案汇总。CLI 是否安装、模型 ID、项目结构和 Git 状态由 Codex 检查，不让用户代查或手填 JSON。时间或费用会显著影响方案时才问预算；默认限制应在最终方案里说明。

模型推荐使用当前会话已核验的信息或无模型调用的环境检查。`doctor` 只检查接口，不证明认证有效。只为查明偏好而做的规划不启动子 CLI 模型。选定的 CLI 不在执行器支持范围时，说明缺口和可行选择，不临时另写适配器或默换模型。

“沿用上次团队”需要能定位到明确的配置；找不到或有多个候选时只问这一点。角色可以复用，模型仍需按执行契约核对，不把案例里的模型写成永久默认值。

## 汇总后开始

收敛后只展示用户需要判断的内容：

- **目标与产物**：做什么、交付到哪里。
- **分工**：成员职责、CLI、完整模型 ID 和 effort；Codex 承担哪些核验与整合。
- **顺序与边界**：谁先做、谁依赖谁、允许改哪些内容。
- **完成标准与限制**：如何验收、调用/时限边界，以及仍有的证据缺口。

完整技术任务表保存在计划中，用户要求时再展开。最后询问是否按这份方案开始，也允许只改其中一项。一般的“帮我做”是进入此引导流程；最终汇总之后的“开始”“就这样”“按这个方案来”才结束默认确认环节。

确认前可以只读检查环境、整理已给材料或保存规划草稿；`run`、`revise`、`dispatch` 等模型调用等待确认。成员讨论也属于模型调用。“先讨论”默认先与主持 Codex 收敛方案。沉默、等待超时或提问工具没有答案都不代表确认。

确认后由 Codex 补齐并校验执行计划，连续完成派发、核验、必要修订与整合；`accept` 是 Codex 的验收记录，不再让用户逐项审批。后续发现会改变已确认目标、模型或范围的问题时，仅说明变化并补问受影响的选择；用户已经明确要求该变更并继续时，直接落实。

确认属于主持对话的行为约定，脚本仍只校验 draft/ready、模型和依赖等执行条件；不要声称 Python 已独立验证人类确认。

## 简短回答与快捷路径

| 用户说法 | 如何处理 |
|---|---|
| “按推荐” / “你定” | 接受当前问题的推荐，补完剩余关键项后仍汇总确认；若已是最终方案，则视为确认该方案。 |
| “都由你定，直接执行，不用再问” | 在已授权范围内选定并展示具体方案后执行；仍处理真正阻塞的歧义与执行检查。 |
| “先展示计划，然后执行” | 属于明确要求直接推进：信息齐全后展示方案并执行；用户说“等我确认”时等待。 |
| “先给方案，别执行” | 只完成规划，保留 draft，等待后续指令。 |
| “沿用上次团队，研究新主题” | 复用明确团队，补问新主题缺少的关键项，汇总新任务。 |
| “现在怎么样” / “暂停” / “继续” | 操作已有任务或组，不重新询问目标、模型和分工；需要时仅消除任务定位歧义。 |

## 简短示例

用户：`$multi-harness 帮我调研 Jev。`

Codex：`这次更想得到能力与使用方式报告，还是结合项目做一个 demo？建议先做报告，确认适用性。`

用户：`报告。`

Codex：基于当前已核验配置，提出研究员与编辑的具体 CLI、模型组合，说明职责，并只问是否采用这一组合。若用户已给出这些信息，跳过这一问。

确定剩余必要边界后，Codex 展示简短方案并等用户说开始，再转入执行契约。整个过程中，用户无需知道 plan.json、task ID、worktree 或派发命令。
